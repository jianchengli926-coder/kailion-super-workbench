# AI 工作台接入指南

> 本文件是把 `公司知识库/`（182 个 Markdown，12 大分类，~2.8MB）接入各类 AI 工具的**操作手册**。
> 核心理念：**AI 干脏活累活（检索→起草→标准化），人做关键决策（核对→发送→跟进）。**
> 任何对外发送/发布/上传动作，必须经 Leo 确认后人工执行（见第五节）。

### 1.2 三类目录的使用姿势

1. **RAG 检索型（02/03/04/05/06/07/09）**：内容量大、按场景取用，向量化 + 元数据过滤。
2. **全文加载型（00/01/08/99）**：规则、事实、配置类，每次会话作为系统提示或上下文直接挂载，不走向量库。
3. **内部隔离型（10/11）**：含成本、利润率、财务预测等敏感数据，**不进入面向客户的 RAG 数据集**，仅在内部工作台通过权限隔离加载。

| **户外刀合规咨询** | `04_国家地区开发指南/11_户外刀各国进口法规专项` | `02_产品知识库/户外刀具/仿牌SKU处理决策` | 目标国合规清单 |

### 2.2 通用检索参数

- **混合检索**：BM25（关键词）+ 向量（Embedding），权重 50:50。
- **重排**：Cross-Encoder / Cohere Rerank，取 Top-5（Dify 生产环境已用 `rerank-multilingual-v3.0`，top_k=8，score_threshold=0.5）。
- **元数据预过滤**：先按 `category` / `region` / `tags` 缩小范围，再做向量检索。例如开发德国客户时先过滤 `region=欧洲` 或 tags 含"德国"。
- **查询改写**：用户输入（如"客户要报价"）先经 LLM 改写为检索词（"报价单 PI 付款条款 物流 FOB 阶梯价 MOQ"）。

## 三、各 AI 工具接入方法

### 3.1 Dify 接入

**已有的两条工作流**（见 `08_AI工作流与工具/Dify工作流/01_Dify工作流总览.md`）：
- 翻译助手（`translation_workflow.yaml`）：只做行业标准术语翻译。
- 双语问答助手（`qa_workflow.yaml`）：基于知识库双语问答，强制引用来源。

**新建数据集步骤：**

1. **创建知识库** → 选择「导入已有文本」→ 批量上传 `公司知识库/` 下所有 `.md`。
2. **分块策略**：
   - 通用默认：**分段 500 tokens，重叠 50 tokens**。
   - 按文档类型微调（见下表）。
3. **索引方式**：高质量向量索引（Embedding）。
4. **Embedding 模型**：双语内容用 `bge-m3`（多语言，1024 维）；纯中文用 `bge-large-zh`；纯英文用 `text-embedding-3-small`。
5. **元数据**：把 YAML frontmatter 的 `title / category / subcategory / tags / region / type / status` 全部解析为元数据字段，启用 metadata filtering。
6. **重排模型**：`rerank-multilingual-v3.0`（Cohere），top_k=8，score_threshold=0.5。
7. **推荐 LLM**：
   - 日常起草/翻译：本地 `qwen2.5:7b`（temperature 0.08–0.1，max_tokens 2048–4096）—— 已在线上跑通。
   - 复杂商务写作/长文：切换 `glm-4.6` / DeepSeek / Claude（按成本与任务难度选）。
   - **禁止口语化**：环境变量 `RULE_NO_COLLOQUIAL = 严禁口语化表达，强制使用行业标准术语`。

**分块参数建议表：**

| 文档类型 | 分块大小 | 重叠 | 分块方式 |
|---|---|---|---|
| 公司简介/品牌故事 | 500–800 tokens | 10–15% | 按段落语义 |
| 产品规格/SKU 参数表 | 300–500 tokens | 10% | 按表格/产品组 |
| SOP/流程类 | 400–600 tokens | 15% | 按步骤 |
| 邮件模板 | 单封为一块 | 0% | 按模板切分 |
| 国家指南 | 600–800 tokens | 10% | 按国家切 |
| 术语库 | 200–300 tokens | 5% | 按术语组 |
| 行业研究 | 500–800 tokens | 15% | 按章节 |

> ⚠️ `10_项目路演与政府材料/` 和 `11_订单与财务/` 含成本/利润率等敏感数据，**单独建私有 dataset，不与面向客户的问答工作流挂接**。

### 3.2 Codex / Cursor 接入

1. **加入工作区**：把 `公司知识库/` 目录加入 Cursor/Codex 项目根目录（不要放进 `.gitignore`，但也不要 push 到公开 repo）。
2. **AGENTS.md / `.cursorrules` 配置**（在项目根新建 `AGENTS.md`）：

   ```markdown
   # KaiLionCrafts 知识库上下文

   - 知识库根目录：./公司知识库/
   - 每次会话必读：
     - @00_导航与规范/02_公司核心事实速查表.md
     - @00_导航与规范/03_术语规范与版本冲突说明.md
   - 全局 AI 规则：@08_AI工作流与工具/01_全局AI指令_核心规则摘要.md
   - 产品参数优先查：@02_产品知识库/
   - 国家/客户查：@04_国家地区开发指南/、@03_客户开发与CRM/
   - 事实冲突时以 00_导航/02 速查表 + 03 版本冲突说明为准。
   - 禁止：编造客户名/成交记录/认证编号；对外输出不得含敏感信息（见 99/03）。
   - 外部动作（发邮件/上架/发布）只生成草稿，由 Leo 确认后人工执行。
   ```

3. **`@文件名` 引用方法**：在对话中直接写 `@03_客户开发与CRM/邮件模板/01_首次开发信模板_多场景.md`，Cursor 会把该文件作为上下文注入。需要哪份读哪份，不要一次性 @ 全部 182 个文件。
4. **独立站开发**：技术栈约束（WordPress + WooCommerce + Elementor + Astra + Rank Math），不得倒退为单文件 SPA；复用优先级 Direct Use → Extend → Modify → Combine → Replace → Rebuild。
5. **Prompt 标准格式**（全局指令第 23 章）：项目背景 → 任务目标 → 涉及文件 → 执行步骤 → 技术约束 → 禁止修改 → 验收标准 → 完成后报告。

### 3.3 自研工作台接入（Streamlit / Prospect / Creator / GoodJob CRM）

公司已部署 4 条工作台线（详见 `08_AI工作流与工具/02_AI工作台体系说明.md`）：

| 工作台 | 地址 | 知识库接入方式 |
|---|---|---|
| Streamlit 企业工作台 | workbench:8501 | 已接 11 个知识库源、1221 个 md |
| Prospect 获客 V75 | prospect:8080 | 内置知识库模块（94 条） |
| KaiLionCreator v2.13 | creator:8766 | LLM 节点支持 RAG/知识库挂载 |
| GoodJob CRM | crm:5188 | 客户档案/PI/WhatsApp，不直接挂 RAG |

**自研索引构建步骤：**

1. 读取 `99_原始资料索引与映射/01_知识库文件全清单.md`，解析为文件清单 JSON（路径 + YAML frontmatter）。
2. 遍历所有 `.md`，按 3.1 的分块策略切片。
3. 为每个 chunk 建立 `chunk_id → file_path → category → tags → region → chunk_text` 映射。
4. 用 `bge-m3` 生成向量，存入向量库（Chroma / Qdrant / FAISS 均可）。
5. 检索时先按 `category / region / tags` 过滤，再向量 + BM25 混合检索，Cohere Rerank 取 Top-5。
6. **前端展示必须带来源**：每个引用块显示 `来源：相对路径 + 章节标题`，方便人工核对。
7. **权限分层**：`10_项目路演`、`11_订单与财务` 不进入面向客户/公网的检索索引；仅内部账号可见。

```text
- 行业/主营：{{industry}}
- 已知痛点或线索：{{any_info}}

【任务】
基于知识库检索结果，写一封不超过 150 词的英文首次开发信。

【要求】
1. 开头必须个性化：提及客户官网产品/参展/采购记录中的一个具体点，证明不是群发。

03_客户开发与CRM/ + 04_国家地区开发指南/{{对应国家}} + 01_公司与品牌/

```

## 五、使用注意事项（红线）

### 5.1 敏感信息处理

以下 13 类信息**不得出现在任何对外输出**（开发信、网站、社媒、客户资料包）中（完整清单见 `99_原始资料索引与映射/03_敏感信息与待补充清单.md`）：

- 统一社会信用代码、法定代表人姓名、创始人手机号、旧手机号
- 工厂股权合作具体比例与条款、合作工厂英文主体名称
- **BSCI 审计 C 评级**（欧洲客户主动问起再视情况沟通，不主动展示）
- 首年财务预测、成本结构、利润率
- 客户具体信息与订单数据（公司 2025 年成立，尚无成交记录，**禁止编造案例**）
- 认证证书具体编号、工厂具体产能数据

> AI 工作台在系统提示中应内置一条硬规则：**"若生成内容包含以上任何字段，必须自动删除后再输出。"**

### 5.2 事实冲突处理优先级

当知识库不同文件出现矛盾时，按以下优先级裁决（详见 `00_导航与规范/03_术语规范与版本冲突说明.md`）：

1. **最高权威**：`00_导航与规范/02_公司核心事实速查表.md`
2. **版本冲突裁决**：`00_导航与规范/03_术语规范与版本冲突说明.md`
3. **公司品牌口径**：`01_公司与品牌/06_版本冲突与权威口径说明.md`
4. 其他文件按 `last_updated` 较新者优先
5. 仍冲突 → 标注 `⚠️ 待 Leo 确认`，不要自行二选一

已裁决的关键口径：
- 创始人姓名 = **利建成**（"李建成"为笔误，已废弃）。
- 工厂关系 = **家族亲属股权直供 + 深度战略合作**（禁止说"自有工厂"）。
- 产品品类 = 四大类（个人护理套装已淘汰）。
- SKU 前缀：厨房刀 = **KL-KN-**（不是 KK）。

### 5.3 外部操作确认机制

AI 只生成草稿，**不自动执行外部动作**。以下动作必须由 Leo 人工确认后执行：

| 动作 | AI 可做 | 人必须做 |
|---|---|---|
| 发邮件 | 起草开发信/回复/跟进序列 | 核对后人工发送（或定时发送前最后一眼） |
| 独立站上架 | 生成标题/描述/Alt/类目 | 人工在 WordPress 后台发布 |
| 社媒发帖 | 生成文案/脚本/标签 | 人工登录账号发布 |
| 报价/PI | 生成草稿 | 核对价格底线（见 03/06 谈判底线表）后签字 |
| 样品/订单 | 生成样品单/PI | 收到定金后才下达生产 |
| 视频/作图 | 生成素材草稿 | 人工筛选后发布 |

> 工作台公网访问走 Cloudflare Tunnel（密码见内部记录），所有工作台共享；Ollama 仅监听 127.0.0.1。

### 5.4 内容安全三层分级（YAML `sensitivity` 字段）

v5.7 起，每个文件的 YAML frontmatter 都带 `sensitivity` 字段，把全库文件分为三层。**物理文件仍留在原目录，不移动；分层只靠 YAML 标记控制 AI 读取范围。**

| 层级 | YAML 值 | 含义 | 典型内容 | 本库文件数 |
|---|---|---|---|---|
| 公开层 | `sensitivity: public` | 可用于官网、社媒、客户邮件；已核验事实、无敏感信息 | 产品介绍/SKU参数、营销文案、公开FAQ、国家指南、行业知识、培训教材、认证矩阵 | 279 |
| 内部层 | `sensitivity: internal` | 仅团队/内部 AI 使用；含成本线索、供应商细节、内部 SOP、未公开策略 | 客户开发SOP/话术、CRM字段、海外仓运营、社媒防封与账号矩阵、AI工作流、独立站运维、导航规范 | 197 |
| 机密层 | `sensitivity: confidential` | **不得输入任何外部 AI**；含合同、利润模型、薪酬、股权、成本拆解 | 销售合同模板、反跳单协议、利润分析与定价模型、订单财务中心方案、绩效考核与提成、股权合作模式、供应链成本拆解模板 | 7 |

**按 AI 环境控制可读范围：**

| AI 环境 | 可读层级 | 说明 |
|---|---|---|
| 外部 AI（ChatGPT / Claude / Gemini / 中转站等公网模型） | **仅 `public`** | 喂给公网模型前，先按 `sensitivity=public` 过滤；`internal/confidential` 一律不得上传 |
| 内部 AI（本地 Dify / Ollama / Codex / Cursor / 本地工作台） | `public` + `internal` | 可用于内部起草、检索、SOP 执行；`confidential` 仍需人工单独放行 |
| 机密材料（合同/利润/薪酬/股权） | **不进任何 AI** | 仅 Leo 本人在本地离线处理，不粘贴进任何对话窗口 |

**按 sensitivity 筛选文件的方法：**

- 命令行：`grep -rl "^sensitivity: public" --include="*.md" .`（把 public 换成 internal/confidential 即可）。
- 上传 Dify/向量库时：解析 YAML 后，把 `sensitivity` 作为元数据字段；**对外 RAG 数据集只导入 `sensitivity=public` 的文件**，`internal` 建私有数据集，`confidential` 不入库。
- Cursor/Codex：在 AGENTS.md 中写明"仅可引用 sensitivity 为 public/internal 的文件；confidential 文件未被显式 @ 时不得读取"。

> ⚠️ 判断原则：**拿不准就标 internal**，不要为了让外部 AI 能用而把内部材料降为 public。

### 5.5 管制刀型产品AI回复硬规则（v6.0新增）

> ⚠️ **AI回答客户咨询时，遇到助力开刀、弹簧刀、自动刀、蝴蝶刀、OTF及疑似仿牌品牌产品，不得主动推荐或报价，统一回复标准话术并转人工处理。**

**触发关键词**：assisted opening、spring assist、switchblade、automatic knife、OTF、butterfly knife、balisong、gravity knife、一键开刀、弹簧刀、自动刀、蝴蝶刀、助力开刀，以及Gerber/SOG/Microtech等疑似仿牌品牌产品咨询。

**标准回复（英文）**："Thank you for your inquiry. This product requires manual compliance review before we can provide pricing or availability. Our team will get back to you within 24 hours."

**标准回复（中文）**："该产品需人工确认市场合规性后回复，我们将在24小时内联系您。"

**系统提示硬规则**：
```
RULE_RESTRICTED_KNIVES: 当客户咨询涉及assisted opening/spring assist/switchblade/automatic/OTF/butterfly/balisong或疑似仿牌品牌产品时，不得给出价格/MOQ/交付信息，必须使用标准话术并标记[转人工]。同时主动推荐合规产品（厨刀/剪刀/厨房用品）。
```

**依据文件**：
- `13_外部知识层/07_管制刀型疑似SKU清单.md`（8个明确管制+2个待核实+11个仿牌）
- `13_外部知识层/04_户外刀具各国法规权威来源汇编.md`（8国官方法规）
- `00_导航与规范/标准问答库.md` 附录（标准话术）

### 5.6 合规兜底规则（v6.0新增）

> ⚠️ **涉及刀具出口合规、认证、关税、各国法规的问题，AI只能引用13_外部知识层中带来源和日期的内容，且必须附上"以官方最新法规为准，需人工二次确认"。**

**系统提示硬规则**：
```
RULE_COMPLIANCE_FALLBACK: 当客户或用户咨询涉及以下主题时——(1)刀具出口合规/进口法规/各国刀具管制，(2)产品认证(LFGB/FDA/CE/REACH等)，(3)HS编码/关税税率/退税，(4)跨境物流限制/承运商政策——AI必须：
1. 只引用13_外部知识层/中明确标注source_url、source_name、fetch_date的内容
2. 不得引用01-12分类中未标注来源的经验性说法作为合规依据
3. 回复末尾必须附上："以上信息基于[来源名称]于[日期]发布的内容，以官方最新法规为准，建议发货/报价前与报关代理或承运商二次确认。"
4. 如13_外部知识层中无对应内容，回复："该问题需人工核实最新法规，请稍候，我们将尽快回复。"不得自行推测或编造法规条款。
```

**适用场景**：
- 客户问"能发XX国吗？" → 引用04_户外刀具各国法规 + 01_物流限制，附兜底声明
- 客户问"关税多少？" → 引用02_HS编码关税，附兜底声明
- 客户问"需要什么认证？" → 引用国家×品类认证矩阵，附兜底声明
- 客户问"你们的刀符合XX国法规吗？" → 引用法规文件，附兜底声明+转人工确认

**依据文件**：
- `13_外部知识层/01_刀具跨境物流限制与承运商政策.md`
- `13_外部知识层/02_刀剪HS编码归类与关税指南.md`
- `13_外部知识层/04_户外刀具各国法规权威来源汇编.md`

### 5.7 跨境网络与内部运营SOP引用限制（v7.0新增）

> ⚠️ **以下内容AI不得主动引用、不得推荐、不得用于对外内容生成：**
> 1. 跨境网络基础设施（自建VPS/Xray/静态住宅IP/软路由分流等）
> 2. 社媒养号SOP（多设备养号、批量加好友、赛马机制等）
> 3. 批量内容生产与多平台运营方法

**系统提示硬规则**：
```
RULE_INTERNAL_SOP: 当AI生成对外内容（官网文案/开发信/社媒帖子/客户邮件/协会分享）时，不得引用以下文件中的具体方法、工具配置或数据：
1. 09_行业知识与培训/协会课程/01_第一章_跨境网络基础设施.md（sensitivity: internal）
2. 09_行业知识与培训/协会课程/05_第五章_海外社媒运营矩阵.md 中的养号/多设备/批量运营部分（sensitivity: internal）
3. 任何标注sensitivity: internal且涉及平台合规风险的运营SOP

如用户主动询问此类内容，回复："该内容为内部技术实践，涉及平台合规风险，不便对外分享。"
```

**适用场景**：
- 客户问"你们怎么管理社媒账号？" → 不引用养号SOP，回复"我们遵循平台规则运营"
- 客户问"你们用什么网络工具？" → 不引用跨境网络配置，回复"我们使用合规的企业网络方案"
- 生成官网/社媒内容 → 不得包含自建跨境网络、多设备养号等细节

**依据文件**：
- `09_行业知识与培训/协会课程/01_第一章_跨境网络基础设施.md`
- `09_行业知识与培训/协会课程/05_第五章_海外社媒运营矩阵.md`
