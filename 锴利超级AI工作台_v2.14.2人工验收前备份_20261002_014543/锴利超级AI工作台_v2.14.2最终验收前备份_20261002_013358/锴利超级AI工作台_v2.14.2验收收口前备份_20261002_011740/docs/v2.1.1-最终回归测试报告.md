## 五、静态代码分析结果（10 项）

### 5.1 DOM ID 匹配
- index.html 定义 114 个 id，JS 引用 231 个去重 id
- 135 个"JS 引用但 HTML 不存在"——**绝大多数为运行时 innerHTML 动态注入的弹窗/表单**（`*-overlay`、`dg-*`、`exp-*` 等），属预期行为
- 18 个 HTML 死 id（CSS/class 引用但 getElementById 未用），不影响功能

### 5.2 全局对象暴露
- `window.Nodes.PARAM_FIELDS` 悬空引用（ui.js L1154）——**本轮已修复**为 `NodeDef.getFields()`
- 其余全局对象均有定义

### 5.3 i18n 完整性
- ZH/EN 词典各 1185 个 key（本轮新增 `api.err.streamError`），**完全对等**
- 代码中 306 次 i18n 调用，**0 个缺失 key**

### 5.4 事件监听器
- 262 处 addEventListener / 23 处 removeEventListener
- 比例悬殊属正常（长运行应用，静态元素无需解绑）
- 动态元素解绑需人工复核的区域：ui.js（76处）、resources.js（58处）、canvas.js（52处）

### 5.5 空引用风险
- 265 处 `getElementById().xxx` / `querySelector().xxx` 未判空
- 绝大多数为"弹窗已注入后再取控件"的顺序调用，真实风险低
- 高风险点：动态渲染列表中 `c.querySelector('.prm-send').addEventListener(...)` 类，若模板缺 class 会抛错

### 5.6 错误处理
- 44 个 async 函数绝大多数有 try/catch
- engine.js:1303 fetch —— **经人工复核为误报**：该 fetch 在 L982 外层 try 块内，L1346 有统一 catch 处理
- JSON.parse 均有 try/catch 包裹
