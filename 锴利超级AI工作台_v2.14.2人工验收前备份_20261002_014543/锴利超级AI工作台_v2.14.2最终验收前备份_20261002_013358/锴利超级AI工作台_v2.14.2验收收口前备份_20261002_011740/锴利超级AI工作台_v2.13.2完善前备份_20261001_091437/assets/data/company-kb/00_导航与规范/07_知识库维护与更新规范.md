# 知识库维护与更新规范

> 本文件是 `公司知识库/` 的**操作规程**。任何人员或 AI 助手新增、修改、废弃知识文件时，必须按本规范执行。
> 适用对象：Leo（人工决策）、AI 工作台（起草/批量更新）、后续接手运营的同事。
> 配套文件：[`04_多级分类体系.md`](./04_多级分类体系.md)（目录树）、[`03_术语规范与版本冲突说明.md`](./03_术语规范与版本冲突说明.md)（权威口径）、[`05_知识库质量审计报告.md`](./05_知识库质量审计报告.md)（审计方法）。

## 一、版本管理规则

### 1.1 版本号格式

```
v{主版本}.{次版本}
```

- 全库只有一个总版本号，记录在 `00_导航与规范/00_README_知识库总导航.md` 顶部"知识库版本"字段与"更新日志"章节。
- 当前基准：**v3.2**（2026-09-27）。本规范与产品匹配矩阵发布后，下次发版统一记为 **v3.3**。

### 1.2 何时升主版本（v3.x → v4.0）

出现以下任一情况，主版本号 +1，次版本归零：

| 触发事件 | 举例 |
|---|---|
| 一级分类（12 大类）增删或重排 | 新增 `12_合规与法务/` 一级目录 |
| 文件整体迁移/重组（>30% 文件换目录） | 把 `11_订单与财务` 拆成两个一级目录 |
| YAML 元数据 schema 变更（必填字段增删） | 必填字段从 7 个改为 9 个 |
| 命名规则或 SKU 编码规则变更 | 厨房刀前缀 `KN` 改为别的（历史教训：KK→KN 已统一，不允许再变） |
| 废弃一个一级分类整目录 | 彻底下线 `10_项目路演` |

### 1.3 何时升次版本（v3.2 → v3.3）

- 新增 ≤15 个知识文件、深化已有文件、修复问题、补充数据。
- 典型：v3.1（独立站技术+AI 工作流深化）、v3.2（订单财务补全+质量审计+AI 接入）。
- **日常小修（改错别字、补一个链接）不单独发版**，攒到下次次版本统一记。

### 1.4 更新日志格式（写进 README 第八节起）

```markdown
## N、v{次版本号}更新日志

**{YYYY-MM-DD} v{x.y} 更新内容：**
- ✅ {做了什么：新建/深化/修复，量化数字}
- ✅ {……}
- ⚠️ {遗留待确认问题 + 责任方}
```

硬性要求：
- 每条以 ✅（完成）或 ⚠️（待确认）开头，动词开头（新建/深化/修复/统一/下线）。
- 带量化数字：文件数、SKU 数、修复处数、MB 压缩率等。
- ⚠️ 条目必须写清"待谁确认、确认什么"，不得只写"待补充"。

## 二、新增资料录入 SOP（6 步流水线）

> 收到任何新资料（客户资料、新 xlsx、新政策、新照片、新录音转写）后，按此顺序处理，**不得跳步**。

```
① 分类判定 → ② 通读原文 → ③ 提炼要点 → ④ 生成 .md → ⑤ 更新索引 → ⑥ 更新映射表
```

| 步骤 | 动作 | 判定标准 / 产出 |
|---|---|---|
| **① 分类** | 先看内容属于 12 大类哪一类 | 用 [`04_多级分类体系.md`](./04_多级分类体系.md) 的目录树对照；拿不准时按"它最常被哪个业务场景调用"归类（客户开发→03，产品参数→02，国家法规→04）。**禁止另起无主题新目录**。 |
| **② 读取** | 完整通读原文，标注关键事实/数字/人名/日期 | 外部资料（PDF/xlsx/录音）先转成可读文本；xlsx 用 pandas 抽行，大图用图片描述库口径记录。 |
| **③ 提炼** | 只留"AI 能直接调用"的结构化知识 | 砍掉寒暄、过程稿、重复表述；保留：结论、参数、阈值、话术、SKU 号、认证名、日期。**原始资料一个字不改、不移、不删**（只读引用）。 |
| **④ 生成文件** | 按本规范第三、四节命名 + 写 YAML + 正文 | 落到对应二级目录，文件名 `两位数字_主题.md`；正文用表格/清单/树状图，不要大段散文。 |
| **⑤ 更新索引** | 同步三处导航 | (a) `00_README` 第七节"快速链接"追加一行；(b) 若新增了 SKU，同时更新该品类 `00_总览` 与 `02_SKU索引`；(c) 结构性增删后更新 [`04_多级分类体系.md`](./04_多级分类体系.md) 与 `知识库思维导图.html`。 |
| **⑥ 更新映射表** | 在 [`99_原始资料索引与映射/02_原始资料→知识库映射表.md`](../99_原始资料索引与映射/02_原始资料→知识库映射表.md) 追加一行 | 记录：原始文件/文件夹名 → 新知识库文件路径 → 一句话说明。无此步 = 资料等于没入库。 |

> ⏱️ **时效要求**：常规资料 24 小时内走完 6 步；影响对外报价/发货/合规的资料（新认证、新法规、新价格）**当天处理并在相关文件顶部标 `🚨 紧急：生效日期 YYYY-MM-DD`**。

## 三、文件命名规范

### 3.1 文件名结构

```
两位数字_主题名.md
```

- **两位数字编号**：`00`–`99`，在同一目录内**唯一、递增、不跳号**。
- `00_` 固定留给该目录的**总览/索引/入口**（如 `00_产品知识库总览.md`、`00_客户开发前知识库查询指南.md`）。
- 主题名用**中文短词**，见名知意，不加空格、不用特殊符号（`/ \ : * ? " < > |` 一律禁用）。
- 分卷大文件用字母后缀：`05_…详情集a.md` / `05_…详情集b.md`（SKU 大数据卷的既定做法）。
- 实例：
  - ✅ `07_知识库维护与更新规范.md`
  - ✅ `12_产品场景与客户匹配矩阵.md`
  - ❌ `new_file.md`（无编号无主题）
  - ❌ `03_客户画像与买家Personas（最终版）.md`（"最终版"不入文件名，版本交给 YAML 与 README 日志）

### 3.2 子目录命名

```
两位数字_可选主题名/   或   纯主题名/
```

- 一级目录固定为 `00_导航与规范` … `11_订单与财务`、`99_原始资料索引与映射`（见 [`04_多级分类体系.md`](./04_多级分类体系.md)，**不新增一级编号**）。
- 二级子目录按业务主题建：`工厂与供应链/`、`邮件模板/`、`Dify工作流/` 等；子目录内文件仍走"两位数字_"编号。

### 3.3 中英文混排规则

- **文件名以中文主题为主**，英文专名（SKU 前缀、产品英文名）可入文件名但不主导：`02_SEO关键词库.md`、`01_RankMath_SEO配置规范.md` 为既有先例。
- 正文里：产品名首次出现写"中文（English）"，其后可单用英文术语；术语必须查 [`03_术语规范与版本冲突说明.md`](./03_术语规范与版本冲突说明.md) 第一节，**禁止自造英译**。
- SKU 号一律大写连字符原样引用：`KL-KN-DS-017`，不写成 `kl-kn-ds-017`（文件系统大小写不敏感，但正文要统一大写）。

## 四、YAML 元数据填写规范

每个 `.md` 文件**必须**以如下 frontmatter 开头（首尾各一行 `---`）。v3.2 质量审计已把全库统一到 7 个必填字段，新增文件不得缺。

```yaml
---
title: 中文标题（与正文 H1 一致）
type: 文件类型
category: 所属一级目录名
tags: [标签1, 标签2, 标签3]
status: active
source: 资料来源（原始文件名或"基于X文件提炼"）
last_updated: YYYY-MM-DD
---
```

### 4.1 各字段取值规范

| 字段 | 必填 | 取值规则 | 示例 |
|---|:---:|---|---|
| `title` | ✅ | 与正文第一行 `# H1` 完全一致 | `产品知识库总览` |
| `type` | ✅ | 从既有词表选，**不新造**：`overview`（总览）/`product_overview`（品类总览）/`sku_index`（SKU索引）/`strategy`（策略画像）/`taxonomy`（分类体系）/`audit_report`（审计）/`pricing`（报价）/`conflict_resolution`（冲突裁决）/`ai_rules`（AI规则）/`maintenance_sop`（维护SOP）/`asset_index`（资产索引） | `maintenance_sop` |
| `category` | ✅ | 必须等于磁盘一级目录名（带编号） | `00_导航与规范`、`03_客户开发与CRM` |
| `subcategory` | 选填 | 二级主题名；属于某二级目录的文件建议填 | `导航与规范`、`客户画像` |
| `tags` | ✅ | 方括号数组，3–8 个，含业务关键词（供 RAG 过滤）；**禁止把敏感词写进 tags** | `[维护规范, 版本管理, SOP, v3.3]` |
| `status` | ✅ | 四选一：`active`（现行有效）/`draft`（草稿待确认）/`deprecated`（已废弃，见第七节）/`archived`（归档只读） | `active` |
| `source` | ✅ | 单行字符串：原始文件名，或"基于 X/Y/Z 文件提炼"；**写第三方外部资料时附检索日期** | `基于 00_README/04分类/05审计 提炼` |
| `last_updated` | ✅ | **严格 `YYYY-MM-DD`**（如 `2026-09-27`），禁止 `2026/9/27` 或 `今天`；每次实质修改正文都要改这个日期 | `2026-09-27` |
| `region` | 选填 | 国家/市场类文件必填，供 RAG 按地区过滤 | `全球`、`欧洲` |

> ⚠️ 历史教训：v3.2 审计时视觉资产库 6 个文件用了非标字段 `date` 而非 `last_updated`、缺 `type/status/source`，共修了 43 处。新文件严禁再犯。

## 五、交叉引用规则

### 5.1 何时加内部链接

- 正文提到"详见某文件/某品类/某法规"时，**必须**给可点的相对路径链接，不要只写文件名。
- 以下位置**必须**互链：品类总览 ↔ SKU 索引 ↔ 参数表；Personas ↔ 匹配矩阵 ↔ 邮件模板；户外刀总览 ↔ 各国法规专项；任何"权威口径"指向 [`02_公司核心事实速查表.md`](./02_公司核心事实速查表.md) 或 [`03_术语规范与版本冲突说明.md`](./03_术语规范与版本冲突说明.md)。

### 5.2 相对路径格式

- 同目录：`./文件名.md`，如 `[术语规范](./03_术语规范与版本冲突说明.md)`。
- 跨一级目录：从二级子目录（如 `02_产品知识库/户外刀具/`）链到另一一级目录，写 `../../一级目录/文件.md`，例：`../../04_国家地区开发指南/11_户外刀各国进口法规专项.md`（该写法已在户外刀总览中验证可用）。从一级目录（如本文件所在 `00_导航与规范/`）链到另一一级目录则用 `../一级目录/文件.md`，可点实例：[户外刀法规专项](../04_国家地区开发指南/户外刀法规专项/11_户外刀各国进口法规专项.md)。
- **只链 `.md` 文件，不链图片二进制**；图片走"图片描述库"文字索引。

### 5.3 避免死链接的检查方法

1. **写完即查**：链接里写的文件名必须和目标目录 `ls` 出来的完全一致（含编号、下划线、`.md`）。v3.2 的 2 处死链接都是"07→08 重命名后 README 没同步"造成的。
2. **重命名/移动文件时**：全局搜旧文件名，把所有指向它的链接一起改（`rg "旧文件名" .`）。
3. **发版前跑一次死链接扫描**（与 v3.2 审计同法）：正则提取全部 `[text](path)`，逐个解析相对路径判存在性，结果应为 **0 死链接**。
4. 链接目标文件若已 `deprecated`，不要直接删链接——改成"该文已废弃，见 `[新文件](正确相对路径)`"。

## 六、定期审计周期与质量检查清单

### 6.1 三级审计节奏

| 周期 | 时间点 | 审计内容 | 产出 |
|---|---|---|---|
| **月度（轻量）** | 每月最后一个周日 | (a) 本月新增/修改文件的 YAML 是否齐全；(b) 新增链接是否死链；(c) 本月有无被标 `draft` 超过 30 天仍未定稿的文件 | 一张 issue 清单（哪几个文件要补什么），记入本文件附录或 README ⚠️ 项 |
| **季度（深度）** | 每季度末 | (a) 全库跑一遍 YAML + 死链接 + 核心事实一致性（同 v3.2 审计脚本）；(b) 对照 [`99/03_敏感信息与待补充清单.md`](../99_原始资料索引与映射/03_敏感信息与待补充清单.md) 清理待办；(c) 检查有无内容重复（8-gram Jaccard > 0.15 报警，a/b 分卷除外） | 追加一份《季度审计报告》章节（仿 [`05_知识库质量审计报告.md`](./05_知识库质量审计报告.md) 格式） |
| **年度（结构）** | 每年 12 月 | (a) 是否需要升主版本（看第一节触发条件）；(b) 12 大类是否仍匹配业务实际；(c) 全库文件数/SKU 数/图片数盘点，更新 README 概览表；(d) `archived` 文件归档清理 | 年度知识库复盘 + 下一年维护计划 |

### 6.2 质量检查清单（每次新增/修改文件后逐项打勾）

- [ ] YAML 7 个必填字段齐全，`last_updated` 为今天 `YYYY-MM-DD`？
- [ ] `category` 与磁盘目录名完全一致？
- [ ] 文件名是"两位数字_主题.md"，编号在本目录内唯一？
- [ ] 正文事实与 [`02_公司核心事实速查表.md`](./02_公司核心事实速查表.md) / [`03_术语规范与版本冲突说明.md`](./03_术语规范与版本冲突说明.md) 无冲突（创始人=利建成、工厂=家族亲属股权直供、四大品类、KN 不是 KK）？
- [ ] 没有把合作工厂的认证/产能写成 KaiLionCrafts 自有？
- [ ] 没有泄露第一节 4.1 列的敏感信息（信用代码、法人手机、BSCI C 级、股权比例、财务预测）？
- [ ] 所有"详见某文件"都给了相对路径链接，且目标存在？
- [ ] 已在 README 快速链接 + `99/02_映射表` 登记？
- [ ] 涉及 SKU 的更新，已同步品类总览 + SKU 索引？

## 七、废弃内容处理流程

### 7.1 旧版本如何标记废弃（不删除）

知识库原则：**旧文件不删，改状态**。

1. 把该文件 YAML 的 `status: active` 改为 `status: deprecated`。
2. 在文件正文最顶部加一行横幅：

   ```markdown
   > ⚠️ **本文件已废弃（废弃日期 YYYY-MM-DD）**，不再作为权威口径。
   > 替代文件：`替代文件路径.md`。废弃原因：{一句话}。
   ```

3. 在 [`03_术语规范与版本冲突说明.md`](./03_术语规范与版本冲突说明.md) 第三节"废弃信息清单"追加一行（废弃信息 / 替代方案 / 废弃原因）——这是全库唯一的废弃登记处。
4. 在 README 快速链接里把指向它的链接改成指向替代文件。
5. 彻底无人引用后，下个季度审计再考虑 `status: archived` 移归档（仍不删盘）。

### 7.2 冲突内容如何裁决（优先级从高到低）

遇到两个文件说法不一致，**按此顺序定权威**，不要各说各话：

1. [`02_公司核心事实速查表.md`](./02_公司核心事实速查表.md)（公司级硬事实最高权威）
2. [`03_术语规范与版本冲突说明.md`](./03_术语规范与版本冲突说明.md)（已登记的冲突裁决）
3. 产品规格 → 以 `02_产品知识库/` 各品类 `02_SKU索引` + `04_SKU完整参数表` 为准（原始 xlsx 兜底）
4. 术语翻译 → 以 `02_产品知识库/术语与材质/` 术语库为准
5. 业务流程/话术 → 以 `03_客户开发与CRM/` 现行 SOP 为准
6. 仍无法裁决 → **不要自己拍板**，在 `99/03_敏感信息与待补充清单.md` 登记"待 Leo 裁决"，正文两说并存并各标 `[有争议，待裁决]`。

> 历史先例：创始人姓名"李建成 vs 利建成"、工厂关系"自有 vs 家族股权直供"、厨房刀前缀"KK vs KN"，均按此流程登记裁决，见 [`03_术语规范与版本冲突说明.md`](./03_术语规范与版本冲突说明.md) 第二节。

### 7.3 敏感信息如何处理

- 严格按 [`03_术语规范与版本冲突说明.md`](./03_术语规范与版本冲突说明.md) 第四节三级分类执行：
  - **内部敏感（不对外）**：统一社会信用代码、法人/创始人手机号、股权比例、财务预测、BSCI 具体评级、工厂股权条款、客户订单数据——写进知识库时**只在内部文件**，且 RAG 面向客户的数据集**不得收录**（见 [`06_AI工作台接入指南.md`](./06_AI工作台接入指南.md) 三类目录隔离）。
  - **内部参考（深度客户可披露）**：合作工厂名、证书编号、产能、成本结构。
  - **可对外**：公司简介、产品目录、认证类型（不写编号/评级）、质保、付款方式、物流方案。
- 新文件若含敏感信息，在 `99/03_敏感信息与待补充清单.md` 登记一条，并在文件顶部加 `🔒 内部敏感，禁止对外` 横幅。

## 八、AI 辅助更新规范

> 原则（沿用 [`06_AI工作台接入指南.md`](./06_AI工作台接入指南.md)）：**AI 干检索/起草/标准化，人做关键决策**。AI 生成的任何文件必须经 Leo 人工核对后再标记 `status: active`。

### 8.1 增量更新指令模板（直接复制使用）

```text
你是 KaiLionCrafts 公司知识库的维护助手。请按《07_知识库维护与更新规范》执行增量更新。

【本次任务】{一句话：新增/修改/废弃哪个主题}
【新资料】{粘贴原文 / 给文件路径}
【目标位置】{一级/二级目录，如 03_客户开发与CRM/}

硬性要求：
1. 先读 00_导航与规范/02_公司核心事实速查表.md 和 03_术语规范与版本冲突说明.md，遵守全部权威口径（创始人=利建成、四大品类、KN 前缀、工厂=家族亲属股权直供）。
2. 不得编造数据：凡是 SKU 号、参数、客户量、认证名，必须来自新资料或既有知识库；知识库没有的数字写"待Leo确认"，不要自己生成。
3. 输出一个 .md 文件，YAML 7 必填字段齐全，last_updated=今天，status=draft。
4. 文件名按"两位数字_主题.md"，编号取该目录现有最大号+1；如不确定编号，先列出该目录现有文件让我确认。
5. 正文用表格/清单，中文为主，产品名首次出现给英文；交叉引用用相对路径。
6. 完成后列出：(a) 新文件路径；(b) 需要我同步更新的 README 链接与 99 映射表条目；(c) 你拿不准、标了 [待确认] 的地方。
不要直接把 status 设为 active，等我核对。
```

### 8.2 质量验收标准（Leo 收到 AI 产出后逐条验收）

| # | 验收项 | 合格标准 |
|---|---|---|
| 1 | 事实零幻觉 | 抽 3 个数字/SKU/认证名回原文核对，全部对得上；对不上即打回 |
| 2 | 口径合规 | 无"李建成/自有工厂/个人护理五品类/KK"等废弃表述；认证都写成"合作工厂" |
| 3 | YAML 合规 | 7 字段齐、`last_updated` 正确、`status` 为 `draft`（未擅自 active） |
| 4 | 命名合规 | 文件名"两位数字_主题.md"，编号不与现有冲突 |
| 5 | 链接可用 | 文中每个 `[text](…)` 都能打开，无死链 |
| 6 | 敏感隔离 | 未把信用代码/手机/BSCI 评级/财务预测写进可对外文件 |
| 7 | 索引闭环 | 已给出 README 链接行 + 99 映射表行，待人工粘贴 |
| 8 | 无过度扩写 | 只提炼资料里有的，不"帮公司补充"不存在的业务 |

> 验收全部通过后，把 `status: draft` 改为 `active`、更新 `last_updated`，并在下次次版本更新日志记一笔。
