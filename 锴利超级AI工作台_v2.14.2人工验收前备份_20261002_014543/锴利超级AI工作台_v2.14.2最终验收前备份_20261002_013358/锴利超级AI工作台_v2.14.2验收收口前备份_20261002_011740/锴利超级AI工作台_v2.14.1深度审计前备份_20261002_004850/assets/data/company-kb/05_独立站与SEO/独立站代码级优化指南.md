# 独立站代码级优化指南

> 站点：kailioncrafts.com（B2B 刀剪询盘型独立站，无在线支付）
> 技术栈：WordPress + WooCommerce + Elementor + Astra Pro + Rank Math + Hostinger(LiteSpeed) + Cloudflare + LiteSpeed Cache
> 目标：移动端 LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1；首页总体积 ≤ 2MB（移动端 ≤ 1.5MB）；请求数 ≤ 50。
> 与其他文件关系：本文件是"代码/插件设置级"操作手册；[`10_网站性能优化与Core Web Vitals.md`](./10_网站性能优化与Core Web Vitals.md) 是指标基线与预算；[`独立站SEO执行清单.md`](./独立站SEO执行清单.md) 是逐项打勾动作表。

## 〇、优化前必读铁律

1. **先备份再动手**：任何代码/插件改动前，UpdraftPlus 手动全量备份一次（见 [`08_独立站技术运维SOP.md`](./08_独立站技术运维SOP.md)）。
2. **本地/ staging 先测**：严禁 AI 直连生产站改代码（见 [`../08_AI工作流与工具/Cursor与Codex外贸工作流.md`](../08_AI工作流与工具/Cursor与Codex外贸工作流.md)）。改完清 LiteSpeed 缓存再上线。
3. **一次只改一类**：开 CSS 优化 → 测首页 → 开 JS Defer → 再测。不要一次全开，出问题无法定位。
4. **改完必测三件事**：① 桌面端首页/产品页/联系页视觉无破版；② 移动端汉堡菜单与 CTA 正常；③ PageSpeed Insights 分数不下降。
5. **测量驱动**：所有优化前后用同一 URL、同一工具（PageSpeed Insights）记录数值，填入本文件末尾的对比表。

## 一、HTML 语义化优化

### 1.1 H1–H6 层级规范

| 规则 | 说明 | WordPress 实现 |
|------|------|---------------|
| 每页**唯一 H1** | H1 必须含 Focus Keyword（见 [`独立站SEO执行清单.md`](./独立站SEO执行清单.md) O-04） | Elementor 编辑页面 → 标题元素 → 标签选 `H1`；Astra 主题默认文章 H1 = 文章标题 |
| 禁止多个 H1 | 首页 Hero 标题是 H1；板块大标题用 H2；卡片标题用 H3 | Elementor 中检查每个 Heading Widget 的 HTML Tag |
| 不跳级 | H1 → H2 → H3，不要 H1 直接跳 H3 | 审计工具：Rank Math 后台自带 Schema/SEO 检查；或用 Chrome 扩展 `HeadingsMap` |
| 产品页 H1 | = 产品名（如 `7Cr17MoV Gyuto Chef Knife 8 Inch`） | WooCommerce 产品标题自动输出 H1，不要在 Elementor 里再加一个 H1 |

**反例**：首页 13 个区块里把每个区块大标题都设成 H1（当前风险点）。**正例**：Hero 一个 H1，其余 12 个区块大标题全是 H2。

### 1.2 语义化 HTML5 标签

Astra 主题已自动输出 `<header>/<nav>/<main>/<article>/<aside>/<footer>`，**不要用 div 套一切**。Elementor 页面建议：

```html
<!-- 推荐结构 -->
<header class="site-header">…</header>
<main id="content">
  <article class="post-content">
    <h1>…</h1>
    <section class="hero">…</section>
    <section class="certifications">…</section>
    <aside class="sidebar-cta">…</aside>
  </article>
</main>
<footer class="site-footer">…</footer>
```

Elementor 中设置：Section → Layout → HTML Tag 选 `main`/`section`；Inner Section 选 `div` 即可。

### 1.3 图片 Alt 文本规范

> 详见 [`SEO规范/03_图片SEO命名规范.md`](./SEO规范/03_图片SEO命名规范.md)。

- 文件名：全小写、连字符、含 SKU，如 `m390-fixed-blade-hunting-knife-detail-kl-od-hc-016.webp`
- Alt ≤ 125 字符，句尾带 SKU，同 SKU 多图 Alt 不雷同
- **装饰性图片 Alt 留空**（`alt=""`），不要写 `product` / `image`
- 产品主图 Alt = `[材质] [品类] [用途] — KaiLionCrafts [SKU]`

WooCommerce 批量补 Alt：后台 → 媒体 → 列表视图，批量编辑 Alt 文本；127 个 SKU 可让 Codex 按 SKU 表批量生成（见 [`../08_AI工作流与工具/Cursor与Codex外贸工作流.md`](../08_AI工作流与工具/Cursor与Codex外贸工作流.md) 批量处理章节）。

### 1.4 链接锚文本

- 导航/正文内链锚文本用**描述性英文**，不要 "click here" / "read more"
- 例：`<a href="/oem-odm/">Explore our OEM/ODM services</a>` ✅；`<a href="/oem-odm/">click here</a>` ❌
- 产品页底部"相关产品"由 WooCommerce 自动输出，锚文本 = 产品名，天然合规

### 1.5 结构化数据（Schema.org）配置

Rank Math 已内置，**不要自己手写 JSON-LD**，避免报错。

| Schema 类型 | 应用页面 | Rank Math 配置位置 |
|------------|---------|-------------------|
| **Organization** | 全站/首页 | Rank Math → Titles & Meta → Local SEO → 填 logo、地址、电话、social |
| **Product** | 127 个产品页 | Rank Math → Products → 自动生成（name/image/sku/brand/offers）；无评价**不要填 aggregateRating** |
| **FAQPage** | 联系页/品类页底部 FAQ | 用 Rank Math FAQ Block 或 Elementor Accordion + Rank Math FAQ 模块 |
| **BreadcrumbList** | 全站 | Rank Math → General → Breadcrumbs → 开启；Astra 已支持 |
| **Article** | 博客文章 | Rank Math → 默认自动输出 |
| **Service** | `/oem-odm/` `/us-warehouse-ready-stock/` | Rank Math → 页面编辑 → Schema → 选 Service |

验证：发布后用 Google Rich Results Test（search.google.com/test/rich-results）抽查首页、1 个产品页、1 个 FAQ 页，0 error 才算过。详见 [`独立站SEO执行清单.md`](./独立站SEO执行清单.md) T-35 ~ T-41。

## 二、CSS 性能优化

> 当前痛点：外观→额外CSS 约 318KB；Font Awesome 全量约 100KB。目标：压缩后 CSS ≤ 150KB。

### 2.1 关键 CSS 内联（Critical CSS）

**LiteSpeed Cache 设置**（后台 → LiteSpeed Cache → CSS Optimizer）：

| 设置项 | 值 | 说明 |
|--------|-----|------|
| Enable CSS Combine | On | 合并外部 CSS |
| Internal CSS Combine | On | 合并内联 CSS |
| CSS Minify | On | 压缩 |
| CSS External Files Include | 留空（默认全部） | 如有 Elementor 报错再排除 |
| Generate Critical CSS | On | 自动生成首屏关键 CSS 内联到 `<head>` |
| Guest Mode Optimization | On | 访客模式下输出优化后 CSS |

> ⚠️ 开 CSS Combine 后必须逐页检查 Elementor 页面是否破版（常见：手风琴/卡片间距错乱）。若破版，把破版 CSS 文件加入 **Exclude** 列表。

### 2.2 未使用 CSS 移除

- **Elementor**：Elementor → Settings → Features → 开启 **Improved CSS Loading**（Load CSS on Demand），只输出当前页面用到的 widget CSS。
- **Elementor → Experiments**：把不用的 widget 设为 Inactive（如 Form、Popup 等未用到的）。
- **Astra**：Astra → Customize → 关闭未用到的模块（如侧栏、面包屑若不用）。
- **WooCommerce 脚本/样式按需加载**：WooCommerce 在首页/博客页不需要加载购物车 JS/CSS。用代码片段（Code Snippets 插件）：

```php
// 非 WooCommerce 页面卸载其样式（放在 Code Snippets 插件）
add_action( 'wp_enqueue_scripts', function () {
    if ( ! is_woocommerce() && ! is_cart() && ! is_checkout() ) {
        wp_dequeue_style( 'woocommerce-general' );
        wp_dequeue_style( 'woocommerce-layout' );
        wp_dequeue_style( 'woocommerce-smallscreen' );
    }
}, 99 );
```

### 2.3 字体优化

当前用 Google Fonts（Inter + Playfair Display）。优化：

1. **`font-display: swap`**：Google Fonts 请求 URL 已带 `&display=swap` ✅（在主题/Elementor 字体设置里确认）。
2. **preconnect**：Astra/Elementor 已自动加；若没有，在 `<head>` 加：
   ```html
   <link rel="preconnect" href="https://fonts.googleapis.com">
   <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
   ```
3. **只加载用到的字重**：不要 400/500/600/700/800 全要，一般 400 + 600 + 700 三档即可。
4. **LiteSpeed → Optimize → Google Fonts Async = On**。
5. **备选：本地自托管字体**（Hostinger 装 OMGF 插件），可省去 DNS 查 fonts.gstatic.com 的开销，但 B2B 站流量小，Google Fonts CDN 已够快，非必需。

### 2.4 干掉 Font Awesome 全量加载

当前 cdnjs 加载 `all.min.css` ≈ 100KB。**替换方案**：

- 优先：把 WhatsApp 图标、社交图标换成**内联 SVG**（几 KB），用 Elementor Icon List 选内置图标。
- 次选：LiteSpeed → CSS Exclude 排除 Font Awesome，只在用到的页面加载。
- 长期：Elementor Pro 自带 Icon Library，不依赖 Font Awesome。

## 三、JavaScript 优化

> 目标：压缩后 JS ≤ 200KB；非关键 JS 全部 Defer。

### 3.1 LiteSpeed JS 设置

后台 → LiteSpeed Cache → JS Optimizer：

| 设置项 | 值 | 备注 |
|--------|-----|------|
| JS Combine | On | 合并 |
| JS Minify | On | 压缩 |
| JS Defer | On | 延迟执行 |
| Delay JS | On（谨慎） | 首屏交互会延迟 3s，需排除关键脚本 |
| Graceful Placeholder | On | Delay JS 期间显示占位 |

**必排除的脚本**（Delay JS Excludes）：

```
/jquery-, /js/jquery, whatsapp, fluentform, ff-calendar, google-analytics, gtag
```

> ⚠️ 开 JS Defer 后必测：① WhatsApp 悬浮按钮可点；② Fluent Forms 提交正常；③ Elementor 手风琴/导航下拉正常。任一坏了就把对应 handle 加进 Excludes。

### 3.2 第三方脚本优化

| 脚本 | 加载位置 | 优化 |
|------|---------|------|
| GA4 / GTM | `<head>` | 用 Insert Headers and Footers 或 GTM；**GA4 部署见** [`12_Google Analytics与数据追踪.md`](./12_Google Analytics与数据追踪.md)。LiteSpeed 可 Delay GA |
| FB Pixel | `<head>` | 若未投广告可暂缓；投了就用 GTM 异步加载 |
| WhatsApp 按钮 | `</body>` 前 | WP WhatsApp 插件已异步；确保不阻塞首屏 |
| YouTube 视频 | 产品页/博客 | LiteSpeed → Media → Lazy Load Iframes = On；视频先显示封面图，点击才加载 |
| Google Maps | 联系页 | 用 lite embed 或点击加载 |

### 3.3 减少 DOM 阻塞

- Elementor → Settings → 关闭不用的 widget 类别（见 2.2）。
- **Wordfence**：关闭 Live Traffic 实时监控（改为每 6 小时扫描），减少数据库写入（见 [`10_网站性能优化与Core Web Vitals.md`](./10_网站性能优化与Core Web Vitals.md) §3.1）。
- **Google Listings & Ads**：如未投 Shopping 广告，停用该插件（前端少一个像素）。
- 审计：Chrome DevTools → Network → 过滤 JS，按大小排序，最大的几个逐个排查是谁加载的。

## 四、图片优化

> 详见 [`SEO规范/03_图片SEO命名规范.md`](./SEO规范/03_图片SEO命名规范.md)。

### 4.1 格式与尺寸规范

| 图片类型 | 最大尺寸 | 格式 | 质量 | 懒加载 |
|---------|---------|------|------|--------|
| 首屏 Hero Banner | 1920×1080（≤ 200KB） | WebP | 80 | **不懒加载**，`fetchpriority="high"` |
| 产品主图 | 1200×1200（≤ 150KB） | WebP | 80 | 详情页主图不懒加载，画廊缩略图懒加载 |
| 产品细节图 | 1200×800 | WebP | 80 | 懒加载 |
| 博客配图 | 1200×630 | WebP | 80 | 懒加载 |
| 工厂/团队照片 | 1600×1000 | WebP | 80 | 懒加载 |

### 4.2 WebP 转换

- **Hostinger Image Optimization 插件**：后台 → Media → Bulk Optimize，一键转 WebP + 压缩。
- **LiteSpeed → Media → WebP Replacement = On**：自动给支持浏览器输出 `.webp`，不支持的回退 jpg。
- 上传前本地用 ShortPixel / Squoosh 压一遍更好，但 Hostinger 插件已够用。

### 4.3 响应式图片与懒加载

- WooCommerce 原生输出 `srcset/sizes`，**不要在 functions.php 里关掉**。
- LiteSpeed → Media → Lazy Load Images = On；Lazy Load Iframes = On。
- **首屏例外**：Hero 图加入 Lazy Load Exclude 列表，并加：
  ```html
  <img src="/wp-content/uploads/hero-kitchen-knives.webp"
       width="1920" height="1080" fetchpriority="high" alt="...">
  ```
  Elementor 中：图片 → Advanced → 给 img 加 `fetchpriority="high"`（或用插件 Preload Featured Images）。

### 4.4 Cloudflare Polish（可选）

Cloudflare 后台 → Speed → Optimization → Polish：
- **Lossless Compression** = On
- **WebP** = On（自动给支持的浏览器发 WebP）
- 注意：已用 LiteSpeed WebP 就不要重复转，避免冲突；二选一即可。

## 五、缓存策略（多层缓存）

```
浏览器 Cache ──→ Cloudflare CDN 边缘缓存 ──→ LiteSpeed 服务器页面缓存 ──→ Redis 对象缓存 ──→ MySQL
```

### 5.1 LiteSpeed Cache 关键配置

| 模块 | 设置项 | 值 |
|------|--------|-----|
| Cache | Cache Enable | On |
| Cache | Cache Logged-in Users | Off |
| Browser Cache | Browser Cache | On |
| Purge | Auto Purge on Publish | On |
| Purge | TTL | 3600（1小时） |
| Object | Object Cache | On（Hostinger 若支持 Redis） |
| ESI | ESI | 可不开（B2B 站无个性化区块需求） |

**缓存命中率目标 > 90%**。后台 → LiteSpeed → Dashboard 查看命中率；< 80% 说明被频繁 Purge，检查是否有插件频繁触发缓存清除。

### 5.2 浏览器缓存（Cache-Control）

LiteSpeed 已自动加。`.htaccess` 兜底（一般不用动）：

```apache
<IfModule mod_expires.c>
ExpiresActive On
ExpiresByType image/webp "access plus 1 month"
ExpiresByType image/jpeg "access plus 1 month"
ExpiresByType text/css "access plus 1 week"
ExpiresByType application/javascript "access plus 1 week"
</IfModule>
```

### 5.3 Cloudflare CDN 缓存

> 部署 9 步见 [`17_五章实战培训课程全案.md`](../09_行业知识与培训/17_五章实战培训课程全案.md) §3.7。

- Caching → Configuration → **Browser Cache TTL = 4 hours**
- Caching → **Crawler Hints = On**
- Speed → **Brotli = On**（压缩比高于 gzip）
- Speed → **Auto Minify**：HTML/CSS/JS 全勾（LiteSpeed 已压过则可不开，避免重复）
- 路由：`/wp-admin/`、`/wp-login.php` 设为 **Bypass Cache**；`/wp-content/uploads/` 设为 **Cache Everything**。

### 5.4 预加载提示（Preload / Prefetch / Preconnect）

在 `<head>` 加（Insert Headers and Footers 插件）：

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<!-- Hero 图预加载 -->
<link rel="preload" as="image" href="/wp-content/uploads/hero-kitchen-knives.webp" fetchpriority="high">
<!-- 预取下一页（可选） -->
<link rel="prefetch" href="/products/">
```

## 六、Core Web Vitals 优化

> 目标值：LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1。详见 [`10_网站性能优化与Core Web Vitals.md`](./10_网站性能优化与Core Web Vitals.md)。

### 6.1 LCP（最大内容绘制）

LCP 元素通常是首屏大图或大段文字。优化动作按优先级：

1. **Hero 图瘦身**：WebP、≤ 200KB、预加载（见 §4.2 / §5.4）。
2. **服务器响应 TTFB < 600ms**：Hostinger 面板开启 OPcache + Redis；PHP 8.1+。
3. **关键 CSS 内联**：不阻塞渲染（§2.1）。
4. **消除第三方阻塞**：GA/WA/聊天工具全部 Delay。
5. **CDN 边缘缓存命中**：Cloudflare + LiteSpeed 双缓存。

### 6.2 INP（交互到下一次绘制，替代 FID）

INP 测的是"点按钮到页面响应"的延迟，主要来自 JS 主线程长任务。

- 开启 LiteSpeed JS Defer + Delay（§3.1）。
- 干掉 Font Awesome 全量（§2.4）。
- Wordfence 关 Live Traffic（§3.3）。
- 用 Chrome DevTools → Performance 面板录一次首页交互，找 Long Task（红色长条 > 50ms），看是哪个脚本。
- 事件委托：Elementor 自己处理，无需业务代码改动。

### 6.3 CLS（累积布局偏移）

CLS 超标 90% 是因为图片/广告位没预留尺寸。

1. **所有 `<img>` 必须写 width/height**：Astra + WooCommerce 默认输出；Elementor 图片 widget 要在设置里填尺寸。
2. **字体置换**：Google Fonts 已 `display=swap`（§2.3）。
3. **广告/聊天按钮**：WhatsApp 悬浮按钮位置固定，不要动态插入文档流。
4. **Web 字体降级**：在 CSS 里给 font-family 加系统字体兜底：
   ```css
   font-family: 'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif;
   ```
5. 顶部通知条（如"Free shipping over $X"）如果动态插入，用 `min-height` 预留高度。

## 七、移动端优化

| 检查项 | 标准 | 验证方式 |
|--------|------|---------|
| 响应式断点 | 390px（iPhone 14 Pro）抽查首页/4 品类/1 产品/联系页 | Chrome DevTools 设备模拟 |
| 触控目标 | CTA 按钮 ≥ 48×48px | 尺量；Fluent Forms 提交按钮已是 52px ✅ |
| 字体大小 | 正文 ≥ 16px（避免 iOS 自动放大） | Astra 默认 16px ✅ |
| 汉堡菜单 | 768px 以下正常展开/收起 | 真机测 |
| 无自动弹窗 | B2B 买家反感 | 不要加 enter-popup |
| `tel:` / `wa.me` | 移动端可点 | 真机点一下 |
| 首屏体积 | ≤ 1.5MB | PageSpeed Insights |

**AMP 要不要做？** 不要。WordPress + AMP 插件和 Elementor/WooCommerce 冲突大，维护成本高；做好响应式 + 图片优化即可达标。

## 八、服务器与托管优化

### 8.1 Hostinger 面板配置

| 项 | 位置 | 推荐值 |
|----|------|--------|
| PHP 版本 | hPanel → Advanced → PHP Configuration | **8.1 或 8.2**（不要用 8.3，插件兼容偶有问题） |
| OPcache | 默认开启 | 确认 `opcache.enable=1` |
| 内存限制 | PHP Config | `256M`（WooCommerce 需要） |
| 最大执行时间 | PHP Config | `300` |
| 上传上限 | PHP Config | `64M`（批量传图） |
| Gzip / Brotli | hPanel 或 Cloudflare | 全开（Cloudflare Brotli 优先） |
| HTTP/2 | 默认开启 | 确认；Cloudflare 自动协商 HTTP/3 (QUIC) |

### 8.2 MySQL 优化

- Hostinger 默认 InnoDB 配置够用，127 SKU 量级无需调优。
- 每月用 WP-Optimize 插件清理一次：修订版、自动草稿、垃圾评论、过期 transient。
- 不要装多余的统计插件（数据全在 GA4）。

### 8.3 TTFB 优化目标

| 环境 | 目标 TTFB |
|------|----------|
| 命中缓存（Cloudflare 边缘） | < 200ms |
| 命中 LiteSpeed 页面缓存 | < 500ms |
| 未命中（动态请求） | < 1s |

测 TTFB：Chrome DevTools → Network → 点首页文档 → Time 面板看 **Waiting (TTFB)**。

## 九、SEO 技术优化（代码层）

> 完整清单见 [`独立站SEO执行清单.md`](./独立站SEO执行清单.md) T-30 ~ T-46。

### 9.1 XML Sitemap

- Rank Math → Sitemap Settings → 开启
- 访问 `https://kailioncrafts.com/sitemap_index.xml` 应能打开
- 提交到 Google Search Console → Sitemaps
- 排除：`/cart/` `/checkout/` `/my-account/` `/wp-admin/`

### 9.2 robots.txt

Rank Math 自动生成。确认包含：

```
User-agent: *
Disallow: /wp-admin/
Disallow: /cart/
Disallow: /checkout/
Disallow: /my-account/
Allow: /wp-content/uploads/

Sitemap: https://kailioncrafts.com/sitemap_index.xml
```

### 9.3 Canonical 与 301

- Rank Math 自动输出 canonical；博客分页 `/insights/page/2/` canonical 指向列表页。
- 旧 URL（如工厂页临时 slug）用 Rank Math → Redirections 做 **301** 到正式 URL。
- 非 www ↔ www 统一（当前 CNAME `www` → 主域，确认 301 不 302）。
- HTTP → HTTPS 301（Hostinger/.htaccess）。

### 9.4 hreflang

当前英文单语站**不需要**。若未来上 `/zh/` 或西语版，用 Rank Math 多语言模块或 WPML，每页输出：

```html
<link rel="alternate" hreflang="en" href="https://kailioncrafts.com/about/">
<link rel="alternate" hreflang="zh-CN" href="https://kailioncrafts.com/zh/about/">
<link rel="alternate" hreflang="x-default" href="https://kailioncrafts.com/about/">
```

### 9.5 404 监控

- 每季度用 Screaming Frog 或 Ahrefs 爬一次全站。
- GSC → 覆盖率报告看"已抓取-尚未索引"/"网址不存在"。
- 404 页已有自定义（`/404.html` ✅），含返回首页 + 搜索 + 热门分类链接。
