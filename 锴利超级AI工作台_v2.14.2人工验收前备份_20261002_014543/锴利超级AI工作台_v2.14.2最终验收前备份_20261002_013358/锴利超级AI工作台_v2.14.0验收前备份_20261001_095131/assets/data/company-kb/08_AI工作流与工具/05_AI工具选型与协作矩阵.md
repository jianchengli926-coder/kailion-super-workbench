# AI 工具选型与协作矩阵

> 本文件回答两个核心问题：**什么任务用什么工具？** 以及 **工具之间怎么配合？**
> 核心原则：AI 干脏活累活（搜索→核证据→写草稿），人做关键决策（检查→发送→跟进）。

## 一、工具全景一览

| 工具 | 定位 | 擅长 | 不擅长 | 访问方式 |
|------|------|------|--------|---------|
| **ChatGPT (GPT-4o/o3)** | 通用大脑 | 需求分析、方案设计、Research、写 Prompt、Code Review | 直接操作代码库、长时运行任务 | chat.openai.com |
| **Claude** | 长文/代码/分析 | 长文档理解、代码生成、架构设计、写作 | 实时数据、多模态生图 | claude.ai |
| **Codex (OpenAI)** | 编码执行者 | 读项目文件、执行开发、Debug、Build、安装依赖、跑测试 | 需求定义、方案探索（应先 Research） | CLI / IDE |
| **Cursor** | AI IDE | 独立站开发、多阶段 UI 重制、精确作用域修改 | 大规模 Research、系统架构设计 | cursor.com |
| **Dify** | 工作流编排 | 双语翻译/问答、RAG 知识库、标准化重复任务 | 灵活创意、一次性复杂任务 | self-hosted |
| **锴利超级工作台 v2.13** | 节点画布 | 节点编排、生成 Word/Excel/PPT/视频、多模型切换 | 深度定制开发 | creator.kailioncrafts.com |
| **企业 AI 工作台 (Streamlit)** | 外贸一体化 | 客户开发+产品 SEO+知识库+127 SKU 管理 | 视频生成、复杂文档工程 | workbench.kailioncrafts.com |
| **V75 获客工作台** | 五步获客闭环 | 找客户→核证→写信→跟进全流程 | 产品管理、SEO | prospect.kailioncrafts.com |
| **GoodJob CRM** | 客户资产 | 客户档案/线索/PI/CI/WhatsApp | 开发信生成、内容创作 | crm.kailioncrafts.com |
| **Ollama 本地** | 本地推理 | qwen2.5:7b 翻译/问答、隐私数据、离线 | 复杂推理、高质量生成 | localhost:11434 |

## 三、默认协作模式：GPT → Codex → GPT 三段式

```
┌─────────┐     ┌─────────┐     ┌─────────┐
│  GPT    │────→│  Codex  │────→│  GPT    │
│ (大脑)  │     │ (双手)  │     │ (验收)  │
└─────────┘     └─────────┘     └─────────┘
   需求分析          执行开发          结果验收
   方案设计          读文件/写代码     Code Review
   Research         Debug/Build       问题诊断
   写 Prompt        安装依赖/测试     下一轮修复
```

### 第一段：GPT（需求理解与方案设计）
- 理解想法、需求分析、项目定义
- 市场/技术 Research、GitHub 项目研究
- 方案设计、MVP 规划、任务拆解
- 生成 Codex 可执行 Prompt
- 输出：开发前研究报告（8 节格式，见全局指令第7节）

### 第二段：Codex（执行开发）
- 阅读项目文件/现有代码
- 分析结构、执行开发、修改/创建文件
- 安装依赖、运行测试、Debug、Build
- 保护用户已有修改
- 输出：完成报告（修改文件/变更/测试/需手动验证/风险）

### 第三段：GPT（验收与诊断）
- Code Review、结果验收
- 问题诊断、下一轮修复 Prompt
- 确认测试通过后宣布完成

> 若 Leo 直接把想法交给 Codex，Codex 应**主动完成需求理解与必要 Research**，不机械写代码。

## 五、各工具优缺点对比

| 工具 | 优点 | 缺点 | 成本 |
|------|------|------|------|
| **GPT-4o/o3** | 综合能力最强、生态最好、插件多 | 上下文有限、数据隐私、订阅费 | ChatGPT Plus 订阅 |
| **Claude** | 长上下文（200K）、代码质量高、写作自然 | 多模态弱、无生图、国内访问需中转 | Claude Pro 订阅 |
| **Codex** | 直接操作代码库、跑测试/Build、保护已有修改 | 需明确 Prompt、不擅长需求探索 | OpenAI 订阅内含 |
| **Cursor** | IDE 内实时编辑、精确作用域、多模型切换 | 大项目性能、需手动圈定范围 | Cursor 订阅 |
| **Dify** | 标准化重复任务、RAG 知识库、工作流可视化 | 不够灵活、需本地 Ollama、维护成本 | 自部署（服务器） |
| **Streamlit 工作台** | 外贸一体化、127 SKU、16 家模型切换 | Python 技术栈、UI 一般 | 自部署 |
| **超级工作台 v2.13** | 节点画布、90节点、真实 Office 文件、多模型 | 数据存浏览器需备份、需服务器常开 | 自部署 |
| **V75 工作台** | 五步获客闭环、25页面、免费模型 | 单文件 HTML 维护难 | 自部署 |
| **GoodJob CRM** | 客户资产沉淀、PI/CI 闭环、Agent 权限控制 | 前后端分离部署复杂 | 自部署 |
| **Ollama 本地** | 免费、隐私、离线、无 API 成本 | 质量不如云端大模型、需硬件 | 免费（电费） |

## 六、模型路由策略（Streamlit 工作台 16 提供商）

工作台支持 16 家模型提供商，按任务路由：

| 任务类型 | 默认模型 | 故障转移 |
|---------|---------|---------|
| 文本生成/开发信 | 豆包/DeepSeek | → 本地 Ollama qwen2.5:7b |
| 深度思考/推理 | DeepSeek-R1 / o3 | → 智谱 glm-4.7-flash |
| 视觉识图 | qwen2.5vl:7b（本地） | → GPT-4o |
| 生图 | 豆包 seedream / DALL-E | → Flux |
| 翻译 | Dify + qwen2.5:7b | → GPT |
| 免费优先 | 智谱 GLM-4-flash（免费） | → Gemini 免费层 |

> 故障转移原则：在线 → 本地，5 分钟缓存。

## 八、工具选择决策树

```
这是什么任务？
├── Level 0：简单问答/翻译/润色
│   └── 直接用 GPT/豆包/Dify，不启动 Research
├── Level 1：改文字/链接/颜色/修 Bug
│   └── Cursor（精确作用域）或 Codex（读文件→改→测）
├── Level 2：新增功能/API/复杂 UI/SEO
│   └── GPT Research → Codex/Cursor 执行 → GPT 验收
├── Level 3：新建网站/SaaS/完整工作流/Skill
│   └── GPT 完整 Research（不从零 Coding）→ Codex 执行 → GPT 验收
├── 客户开发/邮件
│   └── V75 工作台（找客→写信）→ GoodJob CRM（沉淀）
├── 翻译/标准化问答
│   └── Dify 工作流（本地 Ollama）
├── 文档生成（Word/Excel/PPT）
│   └── 超级工作台 v2.13（真实 OOXML）
├── Amazon 运营
│   └── 对应 Codex Skill（14个专项）
└── 视频/图片生成
    └── 超级工作台（9种生图+8种视频模型）
```
