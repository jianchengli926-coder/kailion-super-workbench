# 知识库使用指南与AI读取规范

> 本文件定义知识库的技术规范，确保AI工作台（Dify/Codex/Cursor/自研工作台）能高效、准确地读取和检索本知识库。

---

## 一、文件格式标准

### 1.1 统一格式
- **所有知识文件均为 Markdown (.md) 格式**
- UTF-8 编码，无 BOM
- 换行符为 LF（Unix风格）
- 文件名使用中文+数字前缀，便于排序和识别

### 1.2 YAML Frontmatter 元数据

每个文件开头必须包含以下元数据块：

```yaml
---
title: 文档标题（中文）
type: 文档类型（见下方枚举）
category: 一级分类编号_分类名
subcategory: 二级分类（如有）
tags: [标签1, 标签2, 标签3]
status: active | draft | archived
source: 信息来源（原始文件路径或研究来源URL）
region: global | 北美 | 欧洲 | 东亚 | 东南亚 | 中东 | 拉美 | 俄罗斯CIS | 澳洲 | 南亚
last_updated: 2026-09-27
---
```

## 二、RAG检索优化规范

### 2.1 文档分块策略

| 文档类型 | 推荐分块大小 | 重叠比例 | 分块方式 |
|----------|-------------|---------|----------|
| 公司简介/品牌故事 | 500-800 tokens | 10-15% | 按段落语义分块 |
| 产品规格/SKU索引 | 300-500 tokens | 10% | 按表格/产品组分块 |
| SOP/流程类 | 400-600 tokens | 15% | 按步骤分块 |
| 邮件模板 | 单封邮件为一块 | 0% | 按模板分块 |
| 国家指南 | 600-800 tokens | 10% | 按国家分块 |
| 术语库 | 200-300 tokens | 5% | 按术语组分块 |
| 行业研究 | 500-800 tokens | 15% | 按章节分块 |

### 2.2 检索增强建议

1. **元数据过滤**：利用 `category`、`tags`、`region`、`type` 字段进行预过滤
2. **混合检索**：关键词检索（BM25）+ 向量检索（Embedding），权重 50:50
3. **重排序**：检索结果用 Cross-Encoder 重排序，取 Top-5
4. **查询改写**：用户查询先经LLM改写为更精准的检索词
5. **分类路由**：根据查询意图，先路由到对应一级分类再检索

### 2.3 Embedding 建议

- 中文内容：使用 `bge-large-zh` 或 `m3e-base`
- 英文内容：使用 `text-embedding-3-small` 或 `bge-large-en`
- 双语混合：使用 `bge-m3` 多语言模型
- 维度：1024维（bge-large）或 768维（m3e-base）

## 三、内容编写规范

### 3.1 结构规范
- 每个文件以 `# 一级标题` 开头（与YAML title一致）
- 使用 `##`、`###` 层级组织内容，不超过4级
- 关键信息用**表格**呈现（对比、参数、清单）
- 流程类用**编号列表**
- 注意事项用 `> ⚠️` 引用块标注

### 3.2 敏感信息标注
- 内部敏感信息前加 `⚠️ 内部敏感信息，不宜对外：`
- 待确认信息前加 `⚠️ 待确认：`
- 已废弃信息前加 `❌ 已废弃：`

### 3.3 中英文规范
- 知识库内部说明用**中文**
- 发给海外客户的邮件模板、网站文案用**英文**（可附中文说明）
- 产品术语用**中英对照表格**
- 公司名称、品牌名统一用英文：KaiLionCrafts

### 3.4 数据规范
- 所有数字、参数必须有来源标注
- 日期格式：YYYY-MM-DD
- 货币标注：USD/CNY
- 尺寸标注：公制(mm/cm)为主，英制(inch)为辅

## 四、AI工作台接入指南

### 4.1 Dify 接入
1. 创建知识库数据集，选择"Markdown文件"类型
2. 批量上传 `公司知识库/` 下所有 .md 文件
3. 分块模式：选择"自动"，分块大小 500，重叠 50
4. 索引方式：高质量（Embedding）
5. 设置元数据检索：启用 category、tags、region 过滤

### 4.2 Codex/Cursor 接入
1. 将知识库目录加入项目 `.gitignore` 外的工作区
2. 在 AGENTS.md 中指定知识库路径
3. 使用 `@文件名` 引用特定知识文件
4. 全局指令文件 `08_AI工作流与工具/01_全局AI指令_核心规则摘要.md` 设为系统提示词

### 4.3 自研工作台接入
1. 读取 `99_原始资料索引与映射/` 下的文件清单JSON
2. 建立文件路径→向量的索引映射
3. 实现按分类、标签、地区的过滤检索
4. 前端展示检索结果时，显示来源文件路径

## 五、知识库更新流程

1. **新增资料**：放入对应分类目录，更新YAML元数据，在 `99_原始资料索引与映射/` 中登记
2. **修改内容**：直接编辑对应文件，更新 `last_updated` 日期
3. **废弃内容**：不删除文件，将 `status` 改为 `archived`，在文件开头标注废弃原因
4. **版本冲突**：在 `00_导航与规范/03_术语规范与版本冲突说明.md` 中登记，明确权威版本
5. **季度复盘**：每季度检查一次，更新过时信息，补充新资料

## 六、质量检查清单

每个知识文件入库前需通过以下检查：

- [ ] YAML frontmatter 完整（title/type/category/tags/status/source/last_updated）
- [ ] 文件名符合命名规范（数字前缀_描述性名称.md）
- [ ] 内容结构清晰，标题层级正确
- [ ] 关键数据有来源标注
- [ ] 敏感信息已标注
- [ ] 无编造内容，所有事实可追溯
- [ ] 中英文使用正确
- [ ] 表格格式正确，无错位
- [ ] 与其他文件无事实冲突（或已在冲突说明中登记）
