# 亚马逊运营证据库与数据管理

## 一、运营证据库架构

运营证据库是飞书多维表格形式的结构化运营知识库，包含**8张活跃表、145个字段**，用于记录亚马逊运营全链路的实验、修改和结论。

### 8张活跃表

| 表名 | 字段数 | 用途 |
|------|--------|------|
| ASIN档案 | 15 | 产品基础信息、状态、生命周期 |
| Listing修改记录 | 17 | 每次修改的前后对比、效果观察 |
| 广告实验记录 | 24 | 广告活动调整、竞价变化、ACoS变化 |
| 关键词观察记录 | 13 | 关键词排名、流量、转化追踪 |
| 图片视频版本记录 | 15 | 主图/A+/视频版本迭代 |
| 复盘结论库 | 12 | 周期性复盘的结论和行动项 |
| Skill迭代记录 | 9 | AI工作流/Skill的优化记录 |
| 产品成本利润参数 | 40 | BOM、头程、平台费、毛利率计算 |

### 设计原则
- 以JSON Schema为唯一事实来源创建Base
- Excel仅用于人工审核和备用录入
- 每张表第一字段为主字段
- 跨表关联用文本ID保存
- 不复制任何真实店铺数据（空白部署）

## 二、ASIN档案表（15字段）

记录每个ASIN的核心档案：
- ASIN、产品名称、品牌、类目
- 站点、上架日期、生命周期阶段
- 当前状态（在售/暂停/清仓）
- 目标价格带、目标毛利率
- 负责人、备注

## 三、Listing修改记录表（17字段）

每次修改Listing时必须记录：
- 修改日期、ASIN、修改模块（标题/五点/描述/图片/A+/Search Terms）
- 修改前内容摘要、修改后内容摘要
- 修改原因（基于哪个诊断/数据）
- 预期效果、观察周期（至少14天）
- 实际效果（曝光、点击、转化、排名变化）
- 结论（成功/失败/待观察）
- 回滚方案

### 修改记录规范
- 高或极高保护链接禁止同时替换标题、五点和Search Terms
- 每阶段至少观察14天
- 定义继续、停止和回滚条件
- 不因链接年龄高就自动禁止修改，也不因年龄低就忽略已有流量资产

## 四、广告实验记录表（24字段）

记录每次广告调整：
- 实验日期、ASIN、广告类型（SP/SB/SD）
- 活动名称、广告组、操作实体
- 调整类型（调价/加词/否词/加预算/暂停/新增）
- 调整前值、调整后值
- 调整原因（基于哪个数据/分析）
- 调整前ACoS/TACoS/CVR、调整后ACoS/TACoS/CVR
- 观察周期、实验结论
- 策略依据ID（关联策略指挥官决策）

### 批次管理
- 按批次执行，每批有影响上限
- 每批上传后解析Amazon report.xlsx，闭环成功、失败和待复核
- 达到批次复盘条件后才继续下一批
- 输出0-7天、7-14天、14-30天复盘标准

## 五、关键词观察记录表（13字段）

追踪关键词表现：
- 关键词、ASIN、日期
- 搜索量、流量占比
- 自然排名、广告排名
- 点击量、订单量、CVR
- 关键词状态（核心保护/观察/待否词）
- 变化趋势（上升/下降/稳定）

### 关键词分类追踪
- **必须保护的词**：稳定出单、排名靠前
- **流失词**：之前有排名现在下降
- **无效曝光词**：高曝光无点击/无转化
- **差距词**：竞品有流量但我们没有

## 六、图片视频版本记录表（15字段）

追踪视觉资产迭代：
- ASIN、资产类型（主图/副图/A+/视频）
- 版本号、上传日期
- 设计说明、提示词
- 测试效果（CTR变化、CVR变化）
- 结论

## 七、复盘结论库（12字段）

周期性复盘沉淀：
- 复盘周期、ASIN/店铺
- 核心发现、成功经验
- 失败教训
- 下一步行动
- 责任人、截止日期

## 八、产品成本利润参数表（40字段）

精细化成本核算：
- 产品成本（BOM明细）
- 头程运费
- Amazon平台费（佣金、FBA费）
- 广告成本占比
- 退货率成本
- 毛利率、净利率
- 盈亏平衡点

## 九、飞书归档工作流

### 归档定位
飞书归档是Amazon产出的统一归档入口，本身不生成分析，负责对已完成产物进行分类、预览、确认后上传。

### 六步工作流
1. **预检**：检查lark-cli版本、认证状态、归档配置
2. **构建manifest**：收集artifact路径和任务上下文
3. **分类并生成预览**：映射content_type到Drive路径和Base表
4. **等待用户确认**：展示预览后停止，用户明确确认才执行
5. **执行归档**：上传Drive + 写入Base索引
6. **返回结果**：Drive链接、Base记录链接、状态

### 来源映射
| 来源Skill | content_type | 归档位置 |
|-----------|-------------|----------|
| 竞品调研 | competitor_research_report | 竞品调研资料库 |
| Listing优化 | listing_report / listing_version | Listing档案 |
| 主图副图 | creative_asset | 图片视频版本记录 |
| A+图片 | aplus_asset | 图片视频版本记录 |
| 广告调优 | ad_optimization_report / ad_bulk_file | 广告实验记录 |
| 蓝海调研 | market_research_report | 选品调研档案 |

### 安全规则
- 用户确认前绝不写入Lark
- Drive标签不作为主索引，Base才是事实来源
- 不猜测Base table ID、field ID、record ID或Drive token
- 默认同名文件策略：保留双方，新文件名加时间戳
- 覆盖或删除已有文件属于高风险操作，必须单独确认

## 十、KPI追踪体系

### 核心KPI
| 指标 | 定义 | 追踪频率 |
|------|------|----------|
| Sessions | 店铺/ASIN访客数 | 周 |
| CVR | 转化率 = 订单/Sessions | 周 |
| ACoS | 广告销售成本比 = 广告花费/广告销售 | 日/周 |
| TACoS | 总广告销售成本比 = 广告花费/总销售 | 周 |
| CTR | 点击率 = 点击/曝光 | 周 |
| CPC | 单次点击成本 | 周 |
| BSR | 类目排名 | 日 |
| 评论数/评分 | 社会证明 | 周 |

### 数据权威来源
- 店铺销售、Sessions、店铺CVR、TACoS分母 → Business Report
- SP/SB/SD账户与活动层总盘 → Amazon官方活动报告
- ASIN和广告关系映射 → 领星报告
- 当前Bid、预算、状态 → 最新Bulk

## 十一、数据管理原则

1. **可追溯**：每个结论必须绑定数据来源和时间
2. **版本化**：所有修改有前后对比
3. **证据链**：从假设→实验→数据→结论完整闭环
4. **不伪造**：缺失数据标注`未知`/`未获取`，不写0代替
5. **不静默删除**：原始数据保留，不覆盖历史记录
6. **定期复盘**：0-7天短期、7-14天中期、14-30天长期
