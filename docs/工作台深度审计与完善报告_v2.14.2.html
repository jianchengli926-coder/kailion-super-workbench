后端发现的问题

⚠️ P2: 通用代理无速率限制

/api/proxy 接口无 IP 维度速率限制，公网部署时可能被用于 DoS 放大攻击。影响：中等（本机部署风险低）。建议：添加简单 IP 限流（每IP每分钟60次）。

⚠️ P3: isPublic 判断可读性

server.js:491 运算符优先级未加括号，虽运行正确但易误改。建议：添加明确括号分组。

前端发现的问题

⚠️ P2: 知识库 Markdown 渲染无协议校验

company-kb.js 的 renderMarkdown 对链接 href 和图片 src 未做 javascript: 协议校验。知识库为内部文档，风险较低。建议：添加 http/https/data 协议白名单。

api.js:1109 的 listModels 自行实现 AbortController 和超时，与统一封装不一致。影响：代码可维护性，不影响功能。

⚠️ P3: app.js 全局作用域污染

saveProxyConfig / loadProxyConfig 定义在 IIFE 外部。影响：代码规范，可能被意外覆盖。

📖 八、工作台使用逻辑与模型使用逻辑

工作台使用流程

1. 启动服务器（双击启动器 → 选择本机/局域网模式） 2. 浏览器打开 http://127.0.0.1:8766 3. PIN键盘输入 441723 进入工作台 4. 选择模式： - 🏠 智能工作台：说一句话自动搭建工作流（10个预设模板） - 🖼️ 画布：手动拖拽节点搭建工作流（92种节点） 5. 配置AI供应商（设置 → 供应商管理 → 添加API Key） 6. 运行工作流（并行/串行模式） 7. 查看结果、导出（JSON/PNG/ZIP/共享包）

模型调用逻辑

用户运行工作流 ↓ 节点选择API供应商（如 Ollama本地模型） ↓ engine.js 调用 Failover.chatCompletion(provider, params) ↓ Failover 尝试主供应商 → 成功？→ 返回结果 ↓ 失败 按优先级尝试备用供应商： ① 智谱GLM(免费) → ② 硅基流动(免费) → ③ Gemini(免费) → ④ wawapi → ⑤ OpenAI → ⑥ DeepSeek → ⑦ 豆包 → ⑧ Ollama本地（最后兜底） ↓ 全部失败 → 抛出错误"所有供应商均调用失败" ↓ onProviderUsed 回调记录实际使用的供应商/模型 API Logger 记录调用日志和费用估算

手动切换模型

在画布中选中任意 AI 节点，右侧参数面板的"API供应商"下拉框可手动切换供应商和模型。 手动选择后，该节点使用指定供应商；若调用失败，故障转移仍会自动尝试备用供应商。 设置页的"模型故障转移"开关可全局启用/禁用自动故障转移。
