## P0/P1 问题详情

### P1-1: server.js DNS Rebinding 防护不完整

**位置**：`server.js` 第 202-207 行（校验）与第 422-425 行（实际请求）

**问题描述**：
`validateProxyTarget()` 正确地对 hostname 做了 DNS 解析并检查解析出的 IP 是否为内网地址（防 SSRF）。但实际发起代理请求时，代码使用的是 `target.hostname`（域名）而非已校验的 `validation.resolvedIP`：

```js
// 校验阶段：解析 DNS 并检查 IP
const r = await resolveAndCheckIP(hostname);
return { ok: true, target: target, resolvedIP: r.address };

// 实际请求阶段：又用了 hostname，Node.js 会重新解析 DNS
const proxyReq = client.request({
  hostname: target.hostname,  // ← 重新 DNS 解析！
  port: targetPort,
  ...
});
```

这构成了经典的 **DNS rebinding** 攻击：攻击者控制一个域名，首次 DNS 查询返回公网 IP（通过校验），第二次（实际请求时）返回 `127.0.0.1` 或 `169.254.169.254`，从而绕过 SSRF 防护访问内网服务。

**影响**：公网部署（creator.kailioncrafts.com）时，攻击者可通过代理访问内网 Ollama、云元数据服务等。

**修复建议**：
实际请求使用已校验的 IP 作为 `hostname`，同时通过 `servername` 选项传递原域名以维持 TLS SNI：
```js
const proxyReq = client.request({
  hostname: validation.resolvedIP,  // 使用已校验的 IP
  servername: target.hostname,     // TLS SNI
  port: targetPort,
  ...
});
```

### P1-2: failover.js 用户停止信号未中断故障转移链

**位置**：`failover.js` 第 240-268 行

**问题描述**：
当用户点击"停止"按钮时，Engine 创建的 AbortController 触发 abort，当前 API 调用抛出错误。但 failover 的 catch 块不区分错误类型，将"用户主动取消"当作普通调用失败处理，继续尝试下一个备用供应商：

```js
} catch (err) {
  lastError = err;
  logFailover(currentProvider.name, '调用失败: ' + err.message, 'failed');
  continue;  // ← 用户取消后仍然 continue 到下一个供应商！
}
```

**影响**：用户点击停止后，系统不会立即停止，而是继续遍历所有备用供应商（最多 8-9 个），每个都可能产生 API 调用和费用。

**修复建议**：
在 catch 块中检测用户取消信号，立即 break：
```js
} catch (err) {
  // 用户主动取消 → 立即停止故障转移
  if (opts.signal && opts.signal.aborted) {
    lastError = err;
    break;
  }
  lastError = err;
  logFailover(...);
  continue;
}
```

### P1-3: cors-proxy/server.js 未绑定 localhost

**位置**：`cors-proxy/server.js` 第 259 行

**问题描述**：
代码注释声称"本代理仅监听 localhost"，但实际调用为 `server.listen(port, ...)`，未指定 host 参数。Node.js 默认监听 `::`（所有接口），意味着局域网内任何设备都可以访问此代理。

虽然代理有目标域名白名单（`ALLOWED_TARGET_HOSTS`），但：
1. 白名单包含 `localhost` 和 `127.0.0.1` — 局域网攻击者可通过此代理访问目标机器上的其他本地服务
2. 白名单包含多个 AI API 域名 — 攻击者可利用用户的网络环境访问这些 API（虽消耗的是攻击者自己的 Key）

**修复建议**：
```js
server.listen(port, '127.0.0.1', () => { ... });
```
或通过环境变量 `PROXY_HOST` 控制，默认 `127.0.0.1`。

## 审计方法说明

1. **语法检查**：对全部 48 个项目 JS 文件执行 `node --check`，零错误。
2. **npm audit**：通过 npm registry 扫描已知漏洞，11 个均为构建链依赖。
3. **逐文件人工审计**：实际读取每个文件源码，重点检查：
   - 安全漏洞（SSRF、XSS、路径遍历、API Key 泄露）
   - 异步错误处理（fetch / Promise / AbortController）
   - 内存泄漏（定时器、事件监听）
   - localStorage 损坏处理（JSON.parse try-catch）
   - 版本一致性和已知问题修复验证
4. **版本一致性**：package.json / server.js / index.html / README 四处版本号交叉比对。
