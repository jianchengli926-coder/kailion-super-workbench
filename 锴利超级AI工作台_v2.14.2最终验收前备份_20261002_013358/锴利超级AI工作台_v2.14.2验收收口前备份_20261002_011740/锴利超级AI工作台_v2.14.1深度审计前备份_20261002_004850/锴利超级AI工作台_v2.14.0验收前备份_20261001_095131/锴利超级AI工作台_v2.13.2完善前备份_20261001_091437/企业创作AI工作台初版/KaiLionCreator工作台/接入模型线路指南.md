# 接入你自己的模型 API · 完整指南

> 这份文档回答一件事：**怎么把你自己的 API（豆包 / DeepSeek / GPT / 任意中转站）接进来，让它真正开始干活。**
>
> 实测环境：`https://wawapi.top/v1` + 实测 Key，2026-09-23。

---

## 一、先搞清楚这里有个坑

**浏览器有同源策略。而 AI 中转站几乎都不返回跨域头。**

后果是：网页里 `fetch` 一个中转站，请求会被浏览器**静默拦掉** —— 你在 Network 面板看到的可能是 200，但 JS 里拿到的是一个裸 `TypeError`，连 HTTP 状态码都读不到。

我们实测了 `wawapi.top`：

```
OPTIONS /v1/chat/completions           → 403，无 Access-Control-Allow-Origin
POST    /v1/chat/completions           → 200，但响应头里没有任何 CORS 字段
```

所以：**浏览器直连这条路走不通，这不是配置问题，是架构问题。**

### 解法：本地 API 网桥

`tools/proxy.mjs` —— 一个零依赖的 Node 小程序（只用 Node 内置模块），做四件事：

| 能力 | 说明 |
|---|---|
| 转发 | 把你的请求发到中转站 |
| 补 CORS | 给响应加上 `Access-Control-Allow-Origin`，网页就能读了 |
| 透传 SSE | 流式输出逐块转发，不缓冲 —— 打字机效果不打折 |
| 服务端诊断 | `/diag` 由 Node 直接探测，不受跨域限制，能完整测出能力矩阵 |

**启动：**

```bash
cd kailioncreator
node tools/proxy.mjs
```

窗口别关，让它一直开着。看到这样的输出就对了：

```
  KaiLionCreator · 本地 API 网桥 v1.1.0
  ──────────────────────────────────────────
  监听地址   http://127.0.0.1:8787
  上游代理   http://127.0.0.1:7897/
  ──────────────────────────────────────────
  02:29:58 READY   等待请求…
```

### 关于代理

如果你本机开着 Clash / Surge / v2ray，环境变量里会有 `HTTPS_PROXY`。

**Node 自带的 `fetch` 不吃这个变量** —— 所以会出现「curl 能通、程序不通」的怪现象。网桥里自己实现了 CONNECT 隧道 + TLS 包装，行为和你用 curl 完全一致。

```bash
node tools/proxy.mjs                        # 自动读取系统代理
node tools/proxy.mjs --upstream-proxy http://127.0.0.1:7890
node tools/proxy.mjs --no-upstream-proxy    # 强制直连
node tools/proxy.mjs --allow-private        # 允许转发到内网（Ollama 等）
node tools/proxy.mjs --port 9000
```

高级里还能改：接口路径、额外请求头、是否走网桥、鉴权头名。

## 四、关于生图：为什么这个 Key 生不了图

**记住一句话：多数中转站按「分组」计费，文本和生图是两套独立权限。**

所以很常见的情况是：同一个 Key 文本对话完全正常，生图接口返回：

```
403  Image generation is not enabled for this group
```

**这不是工作台的问题，也不是你配错了。** 两条路：

1. 去中转站后台，给该 Key 所在分组开通图像能力
2. 换一个明确支持生图的 Key（有些中转站生图走单独的分组）

工作台这边**已经全部就绪** —— Key 一开通就能直接用，不需要改任何配置。

### 我们已经替你抹平了协议差异

各家中转站的生图接口长得完全不一样。工作台会自动按顺序尝试**六种形态**：

| # | 形态 | 适配谁 |
|---|---|---|
| 1 | `/images/generations` 标准 | OpenAI / 多数中转站 |
| 2 | `/images/generations` + `response_format: b64_json` | 只返回 base64 的实现 |
| 3 | `/images/generations` + `aspect_ratio` | 认画幅字符串而非像素的实现 |
| 4 | `/models/{model}:generateContent` | Gemini 原生风格 |
| 5 | `/chat/completions` + `modalities:['image','text']` | 把生图当对话的多模态模型 |
| 6 | `/images/edits` + `images[].image_url` | nano-banana 风格 |

**成功一次就记住**（写在 `providers.imageForm`），下次直接命中，不再逐个试。

## 四-b、支持哪些协议（不是只有 OpenAI 兼容）

很多工作台只支持 OpenAI 兼容协议，遇到 Anthropic 或 Gemini 的官方 Key 就直接失败。
这里内置了**四套协议适配**，在「线路管理 → 配置 → 协议」里选：

| 协议 | 实际请求 | 主要差异（都已自动处理） |
|---|---|---|
| **OpenAI 协议** | `POST /chat/completions` | 事实标准，绝大多数中转站和官方都用它 |
| **OpenAI Responses 协议** | `POST /responses` | system 走顶层 `instructions`；消息用 `input` |
| **Claude 协议** | `POST /messages` | ① `max_tokens` **必填**（不填直接 400）② system 是**顶层参数**，不能放进 messages ③ 鉴权必须 `x-api-key` + `anthropic-version` ④ 流式事件名是 `content_block_delta` |
| **Gemini 协议** | `POST /models/{模型}:generateContent` | ① 模型名在 **URL 路径**里 ② role 只有 `user` / `model` ③ system 用 `systemInstruction` ④ 参数放 `generationConfig` ⑤ 流式走 **另一个方法名** `:streamGenerateContent?alt=sse` |

### 选错也没关系：协议会自动纠偏

如果 Base URL 是官方域名，即使协议选错也会被自动纠正：

| 你选的 | Base URL | 实际使用 |
|---|---|---|
| OpenAI 协议 | `api.anthropic.com` | → Claude 协议 |
| OpenAI 协议 | `generativelanguage.googleapis.com` | → Gemini 协议 |
| Claude 协议 | `api.openai.com` | → Claude 协议（按你的选择） |

### 鉴权头会自动匹配协议

选「Claude 协议」但鉴权方式留着默认的 `Bearer`？会自动切成 `x-api-key`。
**同时会带上两种头** —— 官方端点会忽略多余的那个，而中转站往往只认其中一种。
这个刻意的宽容做法能显著减少「配置全对却 401」。

### 多模态：让模型真的"看图"

文本节点接上图片节点后，图片会**按各协议的正确格式**发给模型：

| 协议 | 图片编码方式 |
|---|---|
| OpenAI | `{type:'image_url', image_url:{url}}` |
| OpenAI Responses | `{type:'input_image', image_url}` |
| Claude | `{type:'image', source:{type:'base64', media_type, data}}` |
| Gemini | `{type:'inline_data', mime_type, data}` |

> **一个容易踩的细节**：Gemini 的 `file_data` 需要 Files API 的 URI，普通图片链接不管用。
> 所以工作台在 Gemini 协议下会**自动把远程图取回来内联成 base64**。

有了这个，「产品图 → 卖点文案」「竞品图 → 差异化分析」这类链路才是真的能跑。
单次最多 6 张、单张超过 6MB 自动跳过，避免请求体爆炸。

## 四-c、视频生成（异步任务）

视频和生图完全不是一回事 —— 它是**异步任务**：

```
① 提交任务  →  拿到 task_id
② 轮询状态  →  queued / processing / succeeded
③ 取成片    →  mp4 地址
```

工作台已实现完整链路，并自动尝试 4 种提交形态（Volc `/videos/generations`、
OpenAI `/videos`、通用 `/videos/generations`、Kling `/videos/text2video`），
成功一次就记住。轮询时会自动试多个状态查询路径，并实时把进度显示在节点上。

成片拿到后，结果弹窗里会**直接出现可播放的播放器**，可以下载原片。

> 视频全程可能要几分钟，所以「设置 → 模型调用」里给视频单独配了一个更长的超时（默认 600 秒）。
> 网桥侧的超时是启动参数 `--timeout`，默认 180 秒 —— 视频场景记得加大。

## 五、跑起来看效果

到「经典画布」，放一个文本节点，点「▶ 运行」。

### 怎么分辨真假

| 角标 | 含义 |
|---|---|
| 🟢 绿色 · 显示模型名（如 `gpt-5.5`） | **真实模型产出**。底栏同时显示消耗的 token 数 |
| 🟡 黄色「推演」 | 这个节点没接线路，结果是本地模拟的。**不能当交付物** |
| 🔴 红色「失败」 | 调用出错。右侧参数面板顶部会显示真实原因 + 排查建议 |

### 实测输出

```
真实调用: ✅ 是 · 模型: gpt-5.5 · 线路: 我的中转站 · 主线路
用量: 4496 输入 + 55 输出 = 4551 tokens
输出: 阳江五金刀剪产业的核心竞争力，在于完整高效的产业链、成熟精湛的制造工艺与

```

### 一个我们主动做的设计取舍

**调用失败时，默认不降级。**

上一版会在失败时悄悄改用本地推演 —— 这很危险，因为**你以为拿到了真实结果，其实是假数据**。

现在默认行为是：失败就报错，节点标红，参数面板给出可执行的建议。只有在「设置 → 模型调用」里显式打开「调用失败时降级」才会降级，且结果会被明确标黄。

## 七、错误怎么读

工作台把各家五花八门的报错收敛成**能行动的中文**：

| 你看到的 | 真实含义 | 怎么办 |
|---|---|---|
| `Invalid API key` | 401，Key 无效 | 检查前后空格、是否复制完整、是否用错分组 |
| `Image generation is not enabled for this group` | 403，权限没开 | 去中转站后台开通，或换 Key |
| `上游网关错误（502 Bad Gateway）…` | 中转站临时抖动 | **会自动重试 3 次**，仍失败就等几秒再来 |
| `对方返回了一个网页而不是接口数据（404）` | Base URL 填错 | 补上 `/v1` |
| `浏览器直连失败（很可能是跨域被拦截）` | 网桥没开 | `node tools/proxy.mjs` |
| `连不上本地网桥（http://127.0.0.1:8787）` | 网桥没启动 | 同上 |
| `这条线路没有可用模型` | 模型清单也拉不到 | 检查 Base URL；或手动点「拉取模型」 |

### 自动重试策略

| 情况 | 行为 |
|---|---|
| 5xx（502 / 503 / 520 / 522…）、网络抖动、超时 | **退避重试，最多 4 次尝试**（0.9s → 1.8s → 2.7s） |
| 401 / 403 / 404 / 400 | **立刻失败**（重试没有意义，是配置问题） |
| 你主动取消 | 立刻停止 |

## 八、安全

- **Key 只存在本机**：浏览器 `localStorage`，不上传任何服务器
- **网桥不落盘**：只做本机转发，不留存、不记录你的 Key
- **SSRF 防护**：默认拦截内网地址与云元数据地址（`169.254.169.254`）。要转发到本机 Ollama 需显式加 `--allow-private`
- **备份文件含明文 Key**：导出的 JSON 里有明文，别放公开仓库或云同步目录（设置页有显式警告）

## 十、本地模拟服务（验证协议不用真花 Key）

`tools/mock-ai-server.mjs` 是一个零依赖的假 AI 服务，同时扮演四家厂商：

```bash
node tools/mock-ai-server.mjs --port 8790
# Base URL 填 http://127.0.0.1:8790/v1（Gemini 协议填 /v1beta）
```

| 能力 | 说明 |
|---|---|
| 四套协议 | OpenAI / OpenAI Responses / Anthropic / Gemini，含各自的流式格式 |
| 真实文件 | **真 PNG**（zlib 现场编码）· **真 MP4**（ffmpeg 生成，可直接播放） |
| 视频异步任务 | 提交 → 轮询 N 次 → 完成，完整复现真实链路 |
| 错误注入 | `401 / 403 / 404 / 429 / 500 / 502-HTML` 一键切换 |
| **请求录制** | `GET /__rec` 能看到**实际发出去的请求长什么样** |

最后一条是关键：断言「调用成功」是不够的，要能断言**请求形状对不对**。
比如 Anthropic 的 system 是不是在顶层、Gemini 的模型名是不是在 URL 路径里、
鉴权头有没有切换成 `x-api-key` —— 这些只有看到原始请求才能验。

```bash
# 切换行为模式
curl -X POST http://127.0.0.1:8790/__config -d '{"image":"403"}' -H 'Content-Type: application/json'

# 看收到了什么请求
curl http://127.0.0.1:8790/__rec | python3 -m json.tool | head -50
```

> ⚠️ `verify-providers.mjs` 里**没有**硬编码任何 Key —— 它从环境变量读取。
> 这个文件会进 Git，请不要往里写 Key。
