## 🌍 公网部署详解（Cloudflare Tunnel）

### 原理
通过 Cloudflare Tunnel 将本地 8766 端口暴露到公网，无需公网IP、无需路由器端口映射、自动HTTPS。

### 配置文件
`~/.cloudflared/config.yml`
```yaml
tunnel: kailion-workbench
credentials-file: /Users/a123/.cloudflared/xxx.json
ingress:
  - hostname: creator.kailioncrafts.com
    service: http://127.0.0.1:8766
  - service: http_status:404
```

### 启动隧道（已配置为开机自启）
```bash
cloudflared tunnel run kailion-workbench
```

### 检查隧道状态
```bash
cloudflared tunnel list
cloudflared tunnel info kailion-workbench
```

### 公网访问注意事项
1. **本机服务器必须运行**：公网访问依赖本地服务器，电脑关机或休眠则公网不可用
2. **Cloudflare Tunnel必须运行**：隧道进程停止则公网不可用
3. **数据不共享**：每个用户的工作流、API配置存在自己的浏览器localStorage中
4. **本地Ollama**：公网用户访问时，Ollama走的是你本机的（通过后端代理）

## 📡 局域网部署详解

### 前提条件
1. 本机和同事设备在同一WiFi/局域网
2. 本机IP固定为 192.168.1.22（建议）
3. Mac防火墙允许8766端口

### 固定IP设置
1. 系统设置 → 网络 → 高级 → TCP/IP
2. 配置IPv4为"手动"
3. IP地址：192.168.1.22
4. 子网掩码：255.255.255.0
5. 路由器：192.168.1.1

### 防火墙设置
- 方式1：系统设置 → 网络 → 防火墙 → 关闭防火墙（简单）
- 方式2：添加node例外：
```bash
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --add $(which node)
```

### 同事访问
同事浏览器打开：`http://192.168.1.22:8766`

## 🔑 API Key 配置说明

### 数据存储位置
所有API Key仅保存在**用户自己的浏览器localStorage**中，不上传服务器。

### 多用户使用
- **本机自己用**：配置一次即可
- **同事局域网访问**：同事需要在自己浏览器的设置中配置自己的API Key
- **公网用户访问**：同上，每个用户独立配置

### 快速配置
1. 打开工作台 → 右上角 ⚙ 设置
2. 供应商管理 → 添加供应商
3. 填入 API Base URL 和 API Key
4. 保存即可

## ❓ 常见问题

**Q: 公网访问不了？**
A: 检查3件事：①本地服务器是否运行 ②Cloudflare Tunnel是否运行 ③电脑是否休眠

**Q: 局域网同事访问不了？**
A: 检查：①同一WiFi ②防火墙设置 ③IP地址是否正确

**Q: 图片生成失败"未配置供应商"？**
A: v2.13.1已修复，新建节点自动填充默认供应商。如仍有问题，在设置中确认智谱API Key已配置。

**Q: 电脑休眠后公网断了？**
A: 系统设置 → 电池 → 防止自动休眠，或使用 `caffeinate` 命令保持唤醒。

**Q: 如何更换端口？**
A: 修改启动脚本中的 PORT=8766，同时更新 Cloudflare Tunnel 配置。
