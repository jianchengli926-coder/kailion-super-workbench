## 一、基本信息

### 1.1 技术栈

| 层面 | 技术选型 | 说明 |
|---|---|---|
| 前端框架 | **无框架**，原生 ES Modules | 不依赖 React/Vue/Angular，纯 `import/export` |
| UI 渲染 | 原生 DOM + 模板字符串拼接 | `innerHTML` 注入，无虚拟 DOM |
| 画布引擎 | 自研 SVG 连线 + DOM 节点层 | 贝塞尔曲线连线，无第三方库（无 React Flow / AntV X6） |
| 样式 | 原生 CSS（3 文件，设计令牌制） | CSS 变量驱动主题切换 |
| 后端服务 | **Python 3 HTTP Server**（:8477）+ **Node.js 网桥**（:8787） | 无数据库服务器，无打包工具 |
| 数据持久化 | `localStorage`（元数据）+ `IndexedDB`（图片二进制） | 双存储分离 |
| 文件生成 | 自研 OOXML 打包器（ZIP + XML） | 无 docx/xlsx 库依赖 |
| 图像处理 | 浏览器 Canvas API | 无 Sharp/ImageMagick |
| 包管理 | **无 package.json，无 node_modules** | 零 npm 依赖 |

**关键结论：这是一个零依赖、零构建步骤的纯前端单页应用。** 不需要 `npm install`，不需要 webpack/vite，浏览器直接加载 ES Module 即可运行。

## 四、代码质量

### 4.1 代码组织

- **模块化良好**：按 `core/`（引擎/存储/协议）、`data/`（节点/资源/工作流定义）、`views/`（画布/面板/UI）三层分离
- **ES Module**：严格的 `import/export` 边界，无全局污染
- **无构建步骤**：浏览器原生加载，开发即改即看
- **类组织**：每个视图是一个 ES6 Class（CanvasView、Inspector、NodeLibrary、WorkbenchView 等）
- **事件通信**：通过 `window.dispatchEvent(new CustomEvent(...))` 跨组件通信（如 `klc:selection`、`klc:streaming`、`klc:audit`），是一种简化的事件总线

### 4.2 注释情况

**注释非常丰富**。几乎每个文件头部都有块注释说明用途，关键逻辑旁有行内注释解释"为什么这么做"而非"做了什么"。例如：
- `canvas.js` L523：解释为什么画布不可见时要屏蔽快捷键
- `engine.js` L64-72：解释为什么远程图要先取回本地（CORS）
- `providers.js`：注释详细记录了各协议的坑（Claude 的 max_tokens 必填、Gemini 的 role 只有 user/model）

### 4.3 错误处理

- 网络请求有完善的错误归一化（`ProviderError` 类）
- 失败节点在 UI 上明确标红，附带排查建议
- 存储配额满时有自动清理机制和用户告警
- 单张图片失败不影响整体流程（try-catch 局部兜底）
- 网桥请求失败时降级为浏览器直连尝试

### 4.4 安全性

- **XSS 防护**：所有用户输入通过 `esc()` 函数转义（`canvas.js` L974-976），替换 `<>&"`
- **API Key**：仅存 localStorage，不上传服务器；备份文件含明文 Key 有明确警告
- **SSRF 防护**：网桥 `proxy.mjs` 有 SSRF 防护
- **CORS**：通过本地网桥解决，不暴露 Key 到第三方
- **风险点**：`openResult` 中渲染模型返回内容时，如果包含 HTML 可能有 XSS 风险（需进一步确认 sanitize 逻辑）

### 4.5 性能考虑

- 图片二进制存 IndexedDB 而非 localStorage，避免 localStorage 膨胀
- 素材库图片异步加载（先占位后填 src）
- LOD 缩放折叠减少 DOM 节点渲染压力
- 撤销栈限制 60 步，防止内存无限增长
- 远程图片在下游处理前先取回本地（避免 Canvas 跨域污染）

## 五、优点

### 1. 零依赖、零构建、开箱即用
整个项目没有 `package.json`、没有 `node_modules`、没有 webpack/vite 配置。全部用原生 ES Module 编写，浏览器直接加载。这意味着拷贝整个文件夹到任何有 Python 3 的电脑上双击就能跑，部署成本为零。

### 2. 真实文件生成而非文本伪装
`ooxml.js`（931 行）从零实现了标准 OOXML 打包：Word 产出的是真 `.docx`、Excel 是真 `.xlsx`、PPT 是真 `.pptx`，内部是标准 ZIP + XML 结构，可直接用 Office/WPS 打开编辑。还附带了三层验证（ZIP CRC32 校验、XML 解析、系统工具实测）。这在同类 AI 工作台中很少见。

### 3. 四套 API 协议深度适配，不是简单套壳
`protocols.js` 和 `providers.js` 合计约 1500 行，不是只支持 OpenAI 兼容格式。Claude 的 `max_tokens` 必填、`system` 顶层位置、`x-api-key` 鉴权头；Gemini 的模型名在 URL 路径里、`systemInstruction`、`generationConfig`、不同的流式方法名——这些坑全部处理了。还能根据 Base URL 自动纠正协议选择。

### 4. 本地推演模式保证无 Key 也能完整体验
没配 API Key 时，节点不走空，而是产出结构化的"本地推演"结果（明确标黄角标"推演"），让用户先把流程搭通、做方案排期。配了 Key 就切真实调用。这种"先看流程再花钱"的设计对新手非常友好。

### 5. 完善的工程化测试体系
`tools/` 目录有 10 个测试脚本（约 2400 行），用 Puppeteer 无头 Chrome 跑端到端验证：主冒烟 10 组断言、缺陷回归 9 项、四协议请求形状录制验证、真实文件 CRC32 校验、存储层配额压力测试等。还有 `mock-ai-server.mjs` 模拟四套协议的 AI 服务器，不需要真实 Key 就能跑协议测试。

### 6. 品牌业务深度定制
72 个节点中有 6 个"锴利专线"专属节点（产品图精修、询盘回复、规格表、合规包、供应商评分、独立站文案），资源库中预置了 6 个真实 SKU、12 位行业专家、完整品牌信息。不是通用工具套壳，而是围绕阳江五金刀剪 B2B 出海业务深度定制的。

## 六、缺点

### 1. 大量 innerHTML 拼接，缺少模板层
整个项目用模板字符串拼接 HTML（如 `canvas.js` 的 `el.innerHTML = ...`、`panels.js` 的 `this.root.innerHTML = ...`），没有虚拟 DOM 也没有 diff 机制。每次重渲染都是全量清空再重建（`this.nodeLayer.innerHTML = ''` 然后逐节点 append）。节点数量多时会有性能问题，且容易出 XSS 遗漏。虽然有 `esc()` 函数，但并非所有插值都经过转义。

### 2. 单文件过大，职责耦合
`panels.js` 高达 **2041 行**，一个文件里塞了 NodeLibrary、LibraryView、Inspector、openProviders、openSettings、Copilot 六个类/函数。`providers.js` 1194 行混合了协议路径、鉴权头、聊天、生图、生视频、诊断、预设列表等多种职责。后续维护时定位代码需要大量滚动。

### 3. 无 TypeScript，无类型检查
纯 JavaScript，节点的 params 是动态对象（`node.params[key] = v`），没有类型约束。节点定义中的 fields 和实际 params 之间的对应关系全靠约定，重构时容易出错。也没有 ESLint 配置文件。

### 4. 智能工作台的意图解析是规则匹配，非真 AI
`assistant.js` 的 `parseIntent()` 是关键词/正则匹配（"图片""视频""详情页"等关键词映射到节点类型），不是真正的 LLM 意图理解。用户描述稍复杂就会匹配失败或搭错流程。代码注释中也承认信息不够时会"主动反问澄清"，但实际能力有限。

### 5. 无移动端/平板适配
布局为固定像素（侧边栏 216px + 画布 + 检查器 320px），无媒体查询。在小屏幕上右侧检查器会挤压画布，且节点拖拽交互依赖精确鼠标操作，触屏体验未考虑。

### 6. 供应链节点依赖外部平台前置条件，默认不可用
云牛顿（1688）和妙手 ERP 节点需要用户自己的 AppKey/AppSecret 和 IP 白名单配置，代码中这些节点默认隐藏。虽然这是合理的安全设计，但意味着这 6 个供应链节点对绝大多数用户来说是"看得见摸不着"的。

## 七、使用方法

### 7.1 如何打开/启动

1. macOS 双击 `启动工作台.command`（首次若提示"身份不明开发者"，右键→打开）
2. Windows 双击 `启动工作台.bat`
3. 浏览器自动打开 `http://127.0.0.1:8477`
4. 终端窗口保持开着，关掉工作台就停了

### 7.2 如何配置 API Key

1. 先启动网桥：终端执行 `node tools/proxy.mjs`（或通过启动脚本自动拉起）
2. 顶栏点「线路管理」→「从模板添加」选服务商，或「+ 添加线路」
3. 填三样：**Base URL**（多数带 `/v1`）、**API Key**、**用途**（文本/图像）
4. 点「测试连通」验证（会逐项检查网络/模型清单/对话/流式/生图权限）
5. 到画布放一个节点，点运行；成功后节点右上角出现绿色模型名角标

### 7.3 基本操作流程

**方式一（智能工作台）**：首页输入一句话需求 → 系统自动搭画布并执行 → 可切到经典画布查看/修改

**方式二（经典画布）**：
1. 从左侧节点库拖节点到画布
2. 拖节点上的小圆点连线（out → in）
3. 点节点上的「▶ 运行」
4. 结果自动存入素材库，文档类可下载真实文件

### 7.4 如何备份/导出数据

- 顶栏「设置」→「数据备份」→ 导出完整 ZIP（含工作流、资源库、设置）
- 换电脑时导入该 ZIP 即可恢复
- ⚠️ 备份文件含明文 API Key，不要放公开仓库

### 7.5 常见问题

| 问题 | 解决 |
|---|---|
| 双击 index.html 白屏 | 必须通过启动脚本起 HTTP 服务，不能 file:// 打开 |
| 配了 Key 还走推演 | ①网桥开了吗 ②线路启用了吗 ③Key 填对用途了吗 |
| 生图报 403/未开通权限 | Key 本身没生图权限，去中转站后台开通图像分组 |
| 点运行没反应 | 先查连线，再查提示词是否为空；点工具栏盾牌图标做结构体检 |
| 视频一直转圈 | 视频是异步任务在排队，不要连点运行（会重复扣费） |

## 八、可扩展性

### 8.1 二次开发难度：**中等偏低**

- **优点**：代码结构清晰，注释丰富，无构建工具黑盒，直接改 JS 文件刷新浏览器就能看到效果。节点定义是纯数据驱动的 JSON 结构。
- **缺点**：无 TypeScript 类型提示，无模块热更新，大文件需要仔细定位。

### 8.2 模块化程度

分层清晰：
- `data/nodes.js` 定义节点（纯数据）
- `core/engine.js` 执行逻辑（适配器注册制）
- `views/` 渲染层
- `core/store.js` 状态层

### 8.3 添加新节点的难度：**低**

在 `nodes.js` 中添加一个对象即可：
```js
{ id: 'myNode', name: '我的节点', cat: 'input', icon: '✨',
  desc: '说明', engine: 'llm', kind: 'llm',
  in: [{id:'in', label:'输入'}], out: [{id:'out', label:'输出'}],
  fields: [{key:'text', label:'提示词', type:'textarea'}],
  visible: true }
```
然后在 `engine.js` 中注册对应的 adapter 执行函数。节点库、画布、参数面板会自动识别。

### 8.4 代码可读性：**高**

- 中文注释详尽，解释"为什么"而非"做什么"
- 命名语义化（`this.vp` = viewport、`this.sel` = selection）
- 每个文件头部有块注释说明职责
- 关键设计决策有注释记录（如为什么不自动降级、为什么远程图要先取回本地）
