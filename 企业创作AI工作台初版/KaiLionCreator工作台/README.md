## 快速开始

### 方式一：双击启动（推荐 · Windows 和 macOS 都行）

| 系统 | 双击这个文件 |
|---|---|
| **Windows** | `启动工作台.bat` |
| **macOS** | `启动工作台.command` |
| Linux | 终端执行 `./start.sh` |

启动器会同时拉起**工作台（:8477）**和 **API 网桥（:8787）**，并自动打开浏览器。
那个终端窗口**保持开着** —— 关掉它，工作台就停了。

> ⚠️ **不要直接双击 `index.html`，会白屏。**
> 本项目用的是 ES Module，浏览器禁止 `file://` 协议加载模块 ——
> 这不是"部分浏览器"的问题，是**所有现代浏览器**都这样。
> 必须通过一个本地 http 服务打开，而启动器已经帮你做好了这一步。

> macOS 首次双击 `.command` 若提示「来自身份不明的开发者」：
> 右键点它 →「打开」→ 再确认一次，之后就能正常双击了。

### 方式二：命令行

```bash
cd kailioncreator
python3 -m http.server 8477     # 终端 1：工作台（必需）
node tools/proxy.mjs            # 终端 2：网桥（接真实 API 才需要）
# 浏览器打开 http://127.0.0.1:8477/index.html
```

**目标电脑的环境要求**

| 需要 | 用途 | 没有会怎样 |
|---|---|---|
| **Python 3** | 起本地网站服务 | ❌ 完全打不开 |
| **Node.js** | 跑 API 网桥 | ⚠️ 能打开，但接不了真实 API |

**接自己的模型 API 之前，先开本地网桥**

```bash
node tools/proxy.mjs          # 新开一个终端窗口，让它一直开着
```

> **为什么必须有这一步？** 浏览器有同源策略，而 AI 中转站几乎都不返回跨域头 ——
> 网页直接请求会被**静默拦掉**，连报错都看不到。网桥是一个只跑在本机的小程序，
> 由它代发请求并补上跨域头。它也会自动读取你系统的 `HTTPS_PROXY`，
> 所以本机开着 Clash / Surge 也不影响。
>
> 不接真实模型（只用本地推演）时可以不开。

**方式三：打包成 Windows 桌面应用** → 见 [`桌面版打包指南.md`](./桌面版打包指南.md)

## 上手 3 分钟

1. **打开默认就是「智能工作台」** —— 直接说一句话，例如：
   > `把这张厨房刀具图做成 6 屏电商详情页，目标平台 Amazon，画面文字用 English`

   系统会解析意图 → 自动搭好画布 → 校验前置条件 → 执行并归档。往下滚能看到 4 步执行面板和运行历史。

2. **点顶部「经典画布」** —— 看它到底搭了什么。左边是节点库（可拖拽），中间是画布，右边是参数面板。
   - 从左边拖节点到画布，拖两个节点的小圆点连线，点节点上的「▶ 运行」
   - `Ctrl+O` 自动整理布局，`Ctrl+Z` 撤销，小地图可点击跳转

3. **接上你自己的模型 API** —— 右上角「线路管理」→「从模板添加」或「+ 添加线路」→ 填 Base URL 与 API Key → 点「测试连通」。
   它会**逐项告诉你**真实情况：模型清单能不能拉、对话能不能通、流式是否支持、**生图权限有没有开**，
   每项都给具体原因，不是一句"失败"。

   > 支持任意 OpenAI 兼容服务：官方 Key、one-api / new-api 自建中转、任意第三方中转站、本机 Ollama。
   > 内置模板已预置 OpenAI / DeepSeek / 火山豆包 / 阿里百炼 / Kimi / 智谱 / 硅基流动 / Ollama 等。

   > 没配 Key 也能跑：节点会走**本地推演**，产出结构化结果，方便你先看流程、排期、做方案。
   > 节点右上角会明确标出是**绿色模型名**（真实产出）还是**黄色「推演」**（本地模拟）—— 不会让假数据冒充真结果。

4. **试一条「锴利专线」** —— 左侧「工作流」→ 分类选「锴利专线」→ 加载任意一条：
   - 产品图精修全流程
   - B2B 询盘自动应答
   - 规格表 + 出口合规包
   - 找品 → 询盘 → 供应商评分
   - 独立站文案 + SEO/GEO
   - 跨境合规前置检查

## 真实文件产出（零依赖实现）

这是本工作台与「只演示不产出」的工具最大的区别 —— **文档和图片都是真文件，不是文本伪装**。

**怎么做到的**：`.docx / .xlsx / .pptx` 本质是 ZIP 容器，所以自己写了
[`js/core/zip.js`](./js/core/zip.js)（ZIP 写入器 + CRC32）和
[`js/core/ooxml.js`](./js/core/ooxml.js)（OOXML 生成器）；
图片处理用 Canvas（[`js/core/imagetools.js`](./js/core/imagetools.js)），
PDF 用自研写入器嵌入 JPEG。**没有引入任何第三方库。**

**产出去哪**：选中节点 → 右侧参数面板 →「查看运行结果」→ 顶部主按钮下载。
多文件产出（图像转换 / 宫格分割）可**打包成 ZIP 一次下载**。

**验证强度**（不是"跑通了"，是"真能打开"）：

| 层 | 方法 | 结果 |
|---|---|---|
| ① 结构 | 自研 ZIP 读取器逐条核对本地头 / 长度 / **CRC32** | 全部匹配 |
| ② 内容 | 每个 `.xml` / `.rels` 用 `DOMParser` 解析 | 0 个解析错误 |
| ③ 外部工具 | 写到磁盘后用系统工具再验一遍 | `unzip -t` → No errors detected；`textutil` → 读出 Word 全部正文与表格；Chrome PDF 阅读器 → 渲染出 2 页；Spotlight → 识别为 Microsoft Word / Excel / PowerPoint document |

**一个诚实的边界**：浏览器无法直出**中文 PDF**（需要内嵌 CJK 字体）。
把「文档转换」的目标格式选 PDF 时，会产出排版好的可打印 HTML，
按 `Ctrl/Cmd + P` 另存为 PDF，效果一致。桌面版（Tauri）会调 pandoc / libreoffice 直出。

## 改完代码怎么验证

```bash
chmod +x tools/run-verify.sh && ./tools/run-verify.sh
```

三步：语法预检 → 起三个本地服务（工作台 + 模拟 AI + 测试网桥）→ 无头 Chrome 跑**八套**测试：

| 测试 | 验什么 | 需要 Key？ |
|---|---|---|
| `verify` | 主冒烟 10 组断言 | 否 |
| `verify-bugs` | 缺陷回归 9 项 | 否 |
| `verify-manual` | 使用说明书回归 | 否 |
| `verify-files` | 真实文件产出（ZIP/CRC/XML/PNG/PDF 逐项解包校验） | 否 |
| `verify-protocols` | **四套协议适配**：请求路径 / 鉴权头 / 请求体字段是否符合规范 | 否 |
| `verify-storage` | 存储层（IndexedDB 大对象 / 配额自救 / 完整备份往返） | 否 |
| `verify-fixes` | 本轮审查修复（节点状态写回 / 错误 hint / 视频参考帧） | 否 |
| `verify-providers` | 真实 API 端到端 | 是（缺失自动跳过） |

**前七套不需要任何 API Key** —— 协议验证靠本地模拟服务（`tools/mock-ai-server.mjs`）扮演
OpenAI / Anthropic / Gemini 三家，并提供**请求录制**，能断言「实际发出去的请求形状」是否正确。

**退出码 0 且控制台错误数为 0** 才算通过。产出文件写到 `/tmp/klcout/` 供人工查验。详见 [`tools/README.md`](./tools/README.md)。
